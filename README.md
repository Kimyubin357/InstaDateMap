# 데이트맵

새 장소를 상대방 기기에 알리는 Web Push를 지원합니다. 최초 운영 적용에는 DB 마이그레이션과 VAPID 환경 변수 설정이 필요합니다. [설정 및 검증 안내](docs/push-notifications.md)를 참고하세요.

인스타에서 발견한 곳과 직접 찾은 장소를 둘만의 지도에 모으는 커플용 앱입니다. 사귄 날짜로 만든 여섯 자리 PIN으로 열고, 지도와 리스트로 함께 살펴봅니다.

현재 UI는 아이보리 캔버스 원단·붉은 잉크·짙은 초록을 사용하는 패브릭 실크스크린 테마입니다. 앱 안의 글씨는 제공받은 온글잎 박다현체를 로컬 웹폰트로 사용합니다. 입장·기기 주인 선택에는 새 커플 캐릭터, 설치 아이콘에는 하트 지도 핀 에셋을 적용했습니다. [적용 에셋과 아직 받지 않은 이미지 목록](docs/visual-theme.md)을 참고하세요. 스플래시는 아직 추가하지 않았습니다.

## 이번 버전에 들어 있는 기능

- 날짜에서 만든 YYMMDD PIN, 기기 기억하기, 두 사람 이름 선택, PIN 변경과 기기 잠금
- 전체 화면 지도, 안전 영역 아래의 검색 바·설정, 지도·리스트 아이콘 캡슐, 지도 위 상세 필터와 리스트 정렬 왼쪽의 필터, 최근 저장·가까운순
- 축소 지도는 시·군 → 구 → 행정 읍·면·동 단위로 겹치는 장소를 묶고, 1개뿐인 장소도 숫자 집계핀으로 표시합니다. 숫자는 현재 표시 범위의 장소 수이며 ‘다녀옴·또 갈래·별로’를 방문으로 계산합니다. 여러 장소의 숫자 핀은 확대하고, 1개짜리 핀은 한 번 눌러 위치로 이동하며 장소 카드를 엽니다. 충분히 확대하면 상호명 핀으로 바뀝니다.
- 통합 검색에서 저장된 상호·주소·메모와 카카오의 새 장소를 함께 찾기, 주소 확인 후 저장
- 지도 위 실제 입력칸을 한 번 눌러 검색·취소, 주요 화면을 서버 응답 대기 없이 전환하고 버튼·패널에 짧은 반응 효과 적용
- 기기별 최근 검색 20개와 개별·전체 삭제. 잠금·세션 만료·PIN 변경 시 검색 기록 제거
- IndexedDB에 마지막 조회 내용을 보관하고 DB 변경 알림으로 동기화. 설정·저장 화면 왕복 때 목록과 지도 인스턴스 유지
- 필터는 내용에 맞는 낮은 시트와 초기화·장소 보기 버튼으로 구성하고, 위치 도구와 나란한 원형 ＋ 버튼으로 지도 영역 확보
- 지도 핀 선택 → 장소 카드 → 상세 열기, 손잡이로 시트 펼치기·접기·닫기, 내 위치에서 저장한 장소로 돌아오기
- 인스타 주소에서 게시물 내용·위치 태그로 장소 추출, 여러 장소·지점 확인, 직접 검색
- 인스타 링크 없이 카카오 장소 검색으로 바로 저장
- 중복 병합, 둘 다 저장함, 상태 네 종류, 메모, 주소 복사, 카카오맵 열기
- 실제 처리 단계를 표시하는 링크 저장 진행 화면, 실패한 링크 확인 대기함

영상 속 자막·음성 추출과 기존 DM 가져오기는 아직 구현하지 않았습니다.

## 이번 신뢰성 수정 적용 (R01·R02·R03·R04·R05·R07)

기존 004까지 적용한 DB에 `supabase/migrations/005_reliable_workflows.sql`을 먼저 실행한 뒤 앱을 배포합니다. 장소·메모·원본 연결을 보존하며 재실행할 수 있습니다. 새 설치는 schema → 002 → 003 → 004 → 005 → 006 순서입니다.

- 중단된 분석은 시작 후 90초가 지나면 다음 목록 조회 또는 예약 복구에서 확인 대기로 돌아옵니다. 분석 전체 시간 제한(R10)은 이번 범위에 포함하지 않았습니다.
- 같은 링크는 먼저 시작한 등록 작업이 소유합니다. 선택·보완 화면에서 25초마다 갱신하며, 화면을 떠나면 해제합니다. 앱 강제 종료·오래된 백그라운드 화면은 마지막 갱신 후 90초에 만료됩니다. 만료 후 다른 사람이 다시 시작했다면 이전 화면의 저장을 거절하고 최신 후보를 불러오도록 안내합니다.
- 메모는 원본 버전을 비교합니다. 충돌 시 현재 저장된 내용을 위에, 내 초안을 아래에 보여주고 사용자가 정리해 저장합니다. 자동 병합이나 덮어쓰기 선택창은 추가하지 않았습니다.
- 후보 저장은 선택 번호를 서버의 후보와 대조합니다. 직접 검색한 장소는 검색어와 번호로 카카오를 다시 조회합니다.
- 확인 대기함과 확인 화면의 ‘이 링크 제외하기’는 대기 링크만 제외합니다. 이미 저장한 장소·메모·원본 연결은 유지하고 같은 URL을 다시 등록할 수 있습니다.
- 독립 알림 재시도는 [알림 예약 작업 설정](docs/push-notifications.md#독립-예약-재시도-r07)의 CRON_SECRET·Vault·예약 SQL 설정까지 해야 동작합니다.

R06은 변경하지 않았고 R08~R12는 보류했습니다. 2026-10-24(한국 시간)에 운영 DB·앱 배포·예약 작업까지 적용했습니다. [운영 반영 및 검증 기록](docs/deployment-2026-10-24.md)을 참고하세요.

## 기존 버전에서 업데이트

1. Supabase SQL Editor에서 `supabase/migrations/002_couple_access.sql`, `supabase/migrations/003_board_sync.sql` 순서로 실행합니다. 이미 적용한 002는 건너뛰어도 됩니다. 기존 장소·메모·상태·원본 연결을 보존하며 다시 실행해도 초기화되지 않습니다.
2. 앱을 빌드하고 배포합니다. Git 자동 배포를 쓴다면 마이그레이션을 먼저 적용하세요.
3. **처음 한 번만** 기존 `?t=보드토큰` 주소로 엽니다. 최초 설정 권한을 확인한 뒤 주소에서 토큰을 제거합니다.
4. 사귄 날짜와 두 사람의 이름을 입력하고, 날짜의 YYMMDD 여섯 자리를 한 번 더 확인합니다. 기존 이름은 추천으로 보여주며 수정할 수 있습니다. `익명` 같은 값이 섞여 있어도 설정할 수 있고, 예전 저장자 기록은 바꾸거나 지우지 않습니다.
5. 각 기기에서 본인의 이름을 고릅니다. 이후에는 토큰 없는 기본 주소를 홈 화면에 추가하세요.

PIN 설정 후 기존 토큰은 폐기됩니다. 예전 주소나 `x-board-token`으로 데이터에 접근할 수 없습니다. 실제 날짜와 PIN을 코드·환경 변수·Git에 넣지 마세요.

### iPhone 홈 화면 앱

Safari의 공유 → 홈 화면에 추가에서 **웹 앱으로 열기**를 켭니다. `/enter`에서 추가해도 앱은 항상 기본 지도 주소(`/`)로 시작하며 PIN·이름 선택·지도·저장·설정을 같은 앱 범위로 사용합니다. 입장 후 이동에는 앱 내부 화면 전환을 사용합니다.

PIN 화면에는 없던 주소 표시와 Safari 버튼이 지도에서 나타난다면, 이 PWA 수정 버전을 배포한 뒤 확인해 주세요. 기존 홈 화면 아이콘이 이전 설치 정보를 유지하는 경우 Safari에서 기본 주소를 열어 새 아이콘을 추가한 뒤 확인합니다. 실제 iPhone의 도구막대 표시 여부는 실기기 확인이 필요합니다.

설치용 아이콘은 iPhone용 `apple-icon.png`(180×180), Android용 192×192·512×512 PNG를 제공합니다. **이 아이콘·manifest 변경을 적용한 뒤에는 기존 홈 화면 아이콘을 제거하고 Safari에서 기본 주소를 열어 다시 홈 화면에 추가하세요.** 서버에 저장한 장소는 유지되며 PIN을 다시 입력해야 할 수 있습니다.

키보드가 열리면 시트를 실제 보이는 화면의 높이와 위치에 맞추고, 메모 입력칸을 시트 안에서 보이도록 스크롤합니다. iPhone Safari와 홈 화면 앱에서 메모 입력 → 키보드 닫기 → 시트 드래그를 각각 실기기로 확인해야 합니다.

## 새로 설치

실행 환경은 **Node.js 24.x**, Next.js 16.4.2, React 19.3.1입니다. Vercel에서도 `package.json`의 Node.js 24.x 설정을 사용합니다. 의존성 버전은 `package-lock.json`으로 고정하며, 기존 설치를 재현할 때는 `npm ci`를 사용합니다. 이번 프레임워크 업데이트 자체에는 추가 DB 마이그레이션이 필요하지 않습니다.

1. Supabase 프로젝트를 만들고 `supabase/schema.sql`, `supabase/migrations/002_couple_access.sql`, `supabase/migrations/003_board_sync.sql` 순서로 실행합니다. 초기 스키마에서 받은 보드 토큰은 최초 설정에만 씁니다.
2. `.env.example`을 `.env.local`로 복사하고 다음 값을 채웁니다.
   - `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`: 서버 전용 Supabase 키
   - `KAKAO_REST_API_KEY`, `NEXT_PUBLIC_KAKAO_JS_KEY`: 서버 검색과 브라우저 지도용 키
   - `GEMINI_API_KEY`: 기본 장소 추출 모델. Anthropic 사용 시 `LLM_PROVIDER=anthropic`, `ANTHROPIC_API_KEY` 설정
   - `APP_BASE_URL`: 배포 주소
   - `APP_BOARD_ID`: 보드가 여러 개일 때 사용할 보드 UUID. 커플 하나가 쓰는 기본 구성에서는 생략 가능
3. 카카오 디벨로퍼스에서 카카오맵 사용을 설정하고 배포 주소와 `http://localhost:3000`을 Web 도메인에 등록합니다.
4. `npm install`, `npm run dev`로 실행한 뒤 기존 버전 업데이트의 3~5단계처럼 최초 PIN을 설정합니다.

```sh
npm run dev        # http://localhost:3000
npm test           # 추출·저장·API·인증·스트림 회귀 테스트
npm run typecheck
npm run build
npm run start
```

## 인스타 공유 단축어

예전의 API 직접 호출 단축어 대신 **저장 화면을 여는 방식**을 사용합니다. 단축어 앱에서:

1. 공유 시트 입력으로 URL과 텍스트를 받습니다.
2. 공유한 인스타 링크를 URL 인코딩합니다.
3. `https://배포주소/add?url=인코딩한링크`를 URL 열기로 엽니다.

기억된 기기는 바로 링크를 처리합니다. PIN 입력이나 이름 선택이 필요하면 원래 공유 링크를 유지한 채 해당 화면을 거칩니다. Safari와 홈 화면 웹 앱의 저장 공간이 분리된 경우 각각 처음 한 번 PIN을 입력해야 할 수 있습니다.

장소 후보를 찾으면 중간 확인 버튼 없이 바로 남길 곳·지점을 선택합니다. 후보가 있는 선택 화면에는 재시도 도구를 표시하지 않고, 다른 지점은 개별 장소의 직접 검색으로 찾습니다. 게시물 내용을 읽지 못했거나 지도 후보가 없는 경우에는 링크 재분석과 장소 직접 검색을 제공합니다. 일일 분석 한도 소진은 직접 검색을, 일시적인 요청 제한은 재시도를 먼저 안내합니다.

링크 자동 저장, 후보 선택 저장, 직접 검색 저장이 끝나면 완료 버튼을 한 번 더 누르지 않고 지도로 돌아와 저장한 위치를 보여줍니다. 중복 저장도 지도로 돌아오며 기존 메모·상태를 보존했다는 안내를 표시합니다.

## PIN을 잊었을 때

서버 관리자가 이 프로젝트의 환경 변수를 설정한 터미널에서 `npm run pin:reset`을 실행합니다. 새 PIN을 숨겨 입력받고, 모든 기기의 세션을 만료시킵니다. 보드가 여러 개라면 `APP_BOARD_ID`를 지정하거나 `npm run pin:reset -- --board=보드UUID`를 사용합니다. PIN을 명령 인수로 전달하지 않습니다.

## 데이터와 접근 방식

- PIN은 salt가 있는 scrypt 해시로만 저장합니다. 세션 식별자는 HttpOnly 쿠키, DB에는 그 식별자의 해시만 저장합니다.
- 기기 기억하기는 90일, 선택하지 않으면 브라우저 세션 쿠키와 서버 기준 12시간 만료를 사용합니다.
- PIN 시도 제한은 DB에서 동시 요청을 포함해 집계합니다. 15분 동안 IP별 5회, 보드 전체 30회 실패 시 15분 제한하며 열린 정상 세션은 유지합니다.
- 모든 테이블에 RLS를 적용하고 서버의 service role만 접근합니다. 변경 요청에는 Origin 검증을 적용합니다.
- `place_saves`는 링크 유무와 무관하게 저장자를 기록하고, `source_places`는 인스타 원본 연결을 유지합니다. 장소·저장자·원본 연결은 SQL 함수의 한 트랜잭션으로 저장합니다.
- 인증 조회와 지도 목록에는 HTTP `no-store`를 사용합니다. 조회 데이터의 기기 보관은 인증 범위를 확인한 IndexedDB 캐시로 별도 관리합니다. DB 오류를 빈 지도나 저장 성공으로 처리하지 않습니다.
- 인스타 사진·영상은 저장하지 않으며 장소 상세의 ‘원본 인스타 보러가기’ 버튼으로 원본을 엽니다. 연결된 게시물이 여러 개면 각각의 버튼을 표시하고, 그 아래에 장소 삭제 버튼을 둡니다.

## 기기 캐시와 실시간 갱신

서버 인증 후 마지막 조회 목록을 IndexedDB에서 복원합니다. 설정·저장 화면을 다녀와도 같은 지도와 목록을 유지하며, 캐시가 있으면 서버 갱신 동안 화면 전체를 로딩 상태로 바꾸지 않습니다. 저장·수정·삭제는 온라인에서 서버 성공 후 반영합니다. 저장소 차단·용량 제한·손상 시에는 메모리와 서버 조회로 계속 동작합니다.

DB 트리거가 보드별 변경 번호를 증가시키고, 서버가 비공개 Supabase Realtime 알림을 PIN 쿠키로 보호된 `/api/sync/events` 스트림으로 전달합니다. 브라우저에 DB 권한을 주지 않으며 알림에는 변경 번호만 담습니다. 연속 이벤트는 250ms에 묶고 `/api/places`의 ETag가 같으면 304로 목록 조회를 생략합니다. 스트림은 55초에 재연결하고, 실시간 장애 중에만 열린 화면에서 30초마다 조건부 조회합니다.

네트워크 재연결·앱 복귀 때 놓친 변경을 확인합니다. 연결이 없어도 이미 열린 앱의 마지막 장소는 볼 수 있지만, 인터넷 없이 앱을 처음 실행하거나 지도 타일을 사용하는 기능은 제공하지 않습니다. Safari와 홈 화면 앱의 기기 저장소는 별개일 수 있습니다.

기기 잠금·세션 만료·PIN 변경으로 권한이 없어지면 캐시를 제거하고 다른 탭에도 알립니다. PIN과 세션 식별자·서버 키는 IndexedDB에 저장하지 않습니다. 본인이 PIN을 바꾸면 새 쿠키로 연결을 다시 열고 다른 기기의 기존 세션을 만료시킵니다. 상대방이 내용을 변경해도 작성 중인 메모 초안은 덮어쓰지 않습니다.

## 추출 모듈 추가

`src/lib/extract/types.ts`의 `ExtractorModule` 규격을 구현하고 `router.ts`의 `MODULES`에 등록합니다. 가벼운 모듈은 함께 실행하고, 무거운 모듈은 앞 결과가 부족할 때 실행합니다. 현재 사용자 등록은 인스타 주소와 직접 검색만 지원합니다. 이미지 업로드 모듈은 등록 API에서 호출하지 않으며, Gemini 사용 한도·접근 오류는 앱에 안내합니다. 새 모듈 이름은 DB 체크 제약에도 추가해야 합니다.

## 이번 변경의 검증 기록

- 높이 조절 바텀시트의 X 버튼을 없앴습니다. 모바일 높이 단계는 첨부한 아이폰 화면 비율에 맞춰 최소 48%·중간 63.5%·최대 92%로 설정합니다. 지도·리스트에서 장소 상세를 열면 중간 높이로 시작합니다. 아래로 당길 때는 거리·속도에 관계없이 최대 → 중간 → 최소로 한 번에 한 단계씩 움직이며, 최소에서 다시 충분히 내리면 닫힙니다. 손잡이와 본문 당기기에 같은 규칙을 적용하고 바깥 영역·뒤로가기·미저장 메모 확인은 유지합니다.
- 장소 상세는 본문이 맨 위에 있을 때 새로 아래로 당기면 시트 높이 조절로 이어집니다. 일반 위 방향 스크롤·본문 중간에서 시작한 스크롤·가로 제스처·메모 입력·내부 스크롤은 그대로 두며, 작은 탭 흔들림은 무시합니다. 기존 손잡이와 같은 높이 단계·닫기·미저장 메모 확인을 사용합니다. 내용에서 드래그한 뒤 버튼이 잘못 눌리지 않게 막고 제스처 취소·여러 손가락 입력 시 이전 높이로 돌아갑니다. 필터 등 간결한 시트에는 적용하지 않습니다.
- 이 제스처 변경은 144개 자동 테스트·타입 검사·운영 빌드를 통과했습니다. 전용 Browser 플러그인이 없어 Playwright/Chrome의 실제 터치 이벤트로 390×844·320×600·1440×900에서 손가락 추적·높이 단계 정착, 본문 스크롤 후 맨 위에서 다시 당기기, 가로 스크롤 유지, 버튼 오작동 방지, 취소·멀티터치, 메모 초안 유지와 미저장 상태 닫기 거절, 기존 손잡이·방향키, 작은 화면의 당겨 닫기, 필터·데스크톱 유지와 콘솔 오류 없음을 확인했습니다. 실제 커플 데이터는 수정하지 않았으며 읽기 전용 검증 세션은 정리했습니다. iPhone PWA 실기기 확인은 별도 항목입니다.

- 지도 위 빠른 상태 칩은 제거하고 상세 필터 버튼만 설정 아래에 세로로 정렬했습니다. 검색·설정은 안전 영역 안에서 8px 위로 올렸으며 상태 전체·개별 상태와 장소 종류는 필터 시트에서 선택합니다. 빈 하단 필터 공간은 카드와 지도 도구를 아래로 옮겨 활용합니다. 카드마다 독립된 상세·닫기 버튼을 두어 닫기 버튼도 카드와 함께 스와이프되며 중첩 버튼은 만들지 않습니다. 닫기 터치 영역은 44px이고 키보드 방향키로 넘긴 뒤에도 새 카드에 포커스가 이어집니다.
- 위 배치 변경은 기존 140개 테스트·타입 검사·운영 빌드와 Playwright/Chrome의 390×844·320×600·1440×900 검증을 통과했습니다. 실제 터치 스와이프 중 카드와 닫기 버튼의 이동 거리 일치, 상태·분류 필터와 지도·리스트 공유, 설정 아래 정렬, 카드·도구·탭 겹침 없음, 닫기와 상세 열기 분리, 첫 검색 포커스와 키보드 배경 유지, 같은 지도 인스턴스와 추가 목록 조회 0회, 콘솔 오류 없음을 확인했습니다. 읽기 전용 검증 세션은 정리했고 iPhone PWA 실기기 확인은 별도 항목입니다.

- 지도 핀은 높이 160px 요약 카드로 먼저 열립니다. 좌우 스와이프·데스크톱 화살표·키보드 방향키로 현재 필터의 장소를 넘기며, 선택한 핀과 지도 중심이 함께 바뀝니다. 카드 터치로 위치 미리보기가 있는 상세 시트를 열고 닫으면 같은 카드로 돌아옵니다. 동작 줄이기 설정과 지도 직접 드래그 시 이동 취소를 지원합니다.
- 검색은 기존 입력의 포커스를 유지하며 화면 전체를 덮습니다. 지원하는 iOS에서 화면 전체를 사용하도록 `viewport-fit=cover`와 `black-translucent`를 적용했습니다. 기존 홈 화면 아이콘에 이전 설정이 남으면 삭제 후 Safari에서 다시 추가하고 확인합니다. 다만 최신 iOS 홈 화면 웹앱에서 상태 표시줄 뒤에 임의 콘텐츠를 그리는 기능은 지원하지 않는다는 [WebKit 안내](https://www2.webkit.org/show_bug.cgi?id=317153#c2)가 있으므로, iOS 26.6의 노치 영역까지 지도 타일을 표시한다고 보장하지 않습니다. 지도 배경은 페이지의 맨 위에서 시작하며 조작 요소에만 안전 영역을 적용합니다.
- 키보드가 열릴 때 검색 배경을 `visualViewport.height`로 줄이던 문제를 수정했습니다. 전체 화면의 불투명 배경과 키보드 위의 입력·결과 영역을 분리하고, 검색 중에는 기존 지도 인스턴스를 유지한 채 표시만 숨깁니다. 390×844·320×600·1440×900에서 키보드 높이 300~450px·상단 이동 0~90px, 열기·닫기·포커스 해제·취소를 재현해 배경 비침 없음, 첫 터치 포커스 유지, 같은 지도 복귀, 추가 목록 조회 0회, 콘솔 오류 없음을 확인했습니다. 140개 테스트와 타입 검사·운영 빌드가 통과했으며 실제 iPhone 키보드의 OS 합성 화면은 실기기 확인 항목입니다.
- 카드 변경은 총 140개 자동 테스트·타입 검사·운영 빌드를 통과했습니다. 전용 Browser 플러그인이 없어 Playwright/Chrome의 390×844·320×600·1440×900 화면에서 실제 터치 스와이프, 지도 중간 이동 프레임, 카드에 가리지 않는 핀, 상세 복귀·메모 저장·삭제, 전체 검색, 필터와 단일 카드, 방향키, 동작 줄이기, 화면 왕복 시 같은 지도 유지, 키보드 높이 재현 시 메모 노출을 확인했습니다. 브라우저 콘솔·페이지 오류는 없었고 임시 보드·세션은 정리했습니다. iPhone 홈 화면 앱의 상태 표시줄과 실제 키보드는 실기기 확인 항목입니다.
- 제공된 세 장의 레퍼런스와 최신 브라우저 캡처를 각각 열어 흰 곡면 카드·큰 장소명·원형 화살표·상단 지도 미리보기·두 칸의 정보·하단 주요 동작을 대조했습니다. 사진과 주차 금액 대신 실제 장소의 상태·지역·메모·저장자를 사용하고 기존 코랄 팔레트를 유지했으며, 요청에 맞춰 카드 높이를 160px로 줄였습니다. 앱 화면을 포함한 합성 레퍼런스이므로 개별 앱은 위의 모바일·데스크톱 크기로 비교했습니다.

- 기존 회귀 검증을 유지하며 총 119개 자동 테스트 통과. 캐시 장애·인증 범위·응답 순서·변경 번호·304·실시간 구독 정리·재연결·만료·초기 연결 복구를 포함합니다.
- 운영 빌드와 실제 Supabase·카카오 API를 임시 보드·두 브라우저 기기로 검증했습니다. 설정·저장 화면 왕복 시 추가 장소 조회 0회와 같은 지도 DOM 유지, IndexedDB 우선 복원·손상 복구, 실시간 장소·상태·저장자·확인 대기·삭제 반영, 오프라인 복귀, 메모 초안 보존, 저장 직후 표시, PIN 변경 및 다른 기기·탭의 캐시 제거를 확인했습니다. 임시 보드를 삭제했고 실제 커플의 PIN은 유지했습니다.
- 실제 Supabase·카카오·장소 추출 API와 별도 임시 보드로 최초 설정 → 두 기기 입장·이름 선택 → 공유 링크·직접 검색 → 중복 병합 → 메모·상태 → PIN 변경을 확인했습니다. 공유한 인스타 릴스는 도나스데이 본점으로 저장되고 곧바로 목록에 나타났습니다.
- 잘못된 PIN 5회 후 IP 제한, 동시 40건 중 보드 제한 30건 적용, 정상 세션 유지, 서버 만료, 기기 잠금, 외부 Origin 및 폐기된 토큰 거절을 확인했습니다. 트랜잭션 오류는 고아 장소를 남기지 않았습니다.
- 운영 모드에서 삭제 후 같은 링크 재저장, 실패 후 재시도, 메모·상태 보존, 확인 대기함의 직접 검색·확인 후 저장을 확인했습니다.
- 전용 Browser 플러그인이 제공되지 않아 Playwright와 설치된 Chrome으로 검증했습니다. 390×844, 1440×900 및 높이 560 화면에서 검색·뒤로가기·포커스 복귀·Escape·위치 권한 거절·스크롤을 확인했습니다. 숫자 키보드 속성과 PIN 표시 전환도 확인했습니다.
- 필터·저장 흐름 변경은 운영 빌드와 로컬 분리 데이터로 검증했습니다. 낮은 필터 시트·하단 버튼·포커스·뒤로가기, 후보 화면 바로 이동, 저장 오류 후 재시도, 저장·중복·직접 검색 후 지도 복귀와 목록 갱신을 확인했습니다. 실제 카카오 지도 SDK를 사용했으며 이번 UI 검증은 운영 Supabase 데이터와 PIN에 접근하지 않습니다. 자동 저장 분석 결과와 검색 결과는 검증용 응답을 사용했습니다.
- 화면 전체의 핀치 확대는 제한하고 지도 자체의 확대·축소는 유지합니다. 작은 입력 글씨로 인한 iPhone 자동 확대를 피하도록 모바일 검색·정렬·메모 입력은 16px로 맞췄습니다. Chrome 모바일 터치 재현에서 일반 UI 배율 유지, 카카오 지도 배율 변경, 리스트·패널 스크롤과 패널 드래그를 확인했습니다. iPhone 홈 화면 앱의 실제 동작은 실기기 확인 항목입니다.

이하 표는 이전 흰 바탕·코랄 테마의 검증 기록입니다. 현재 패브릭 테마는 위의 제작 안내를 기준으로 합니다. 당시 PIN 시안은 휴대폰 여러 대를 합친 이미지여서 개별 화면은 390×844 크기로 비교했습니다.

시안의 핵심 구성과 실제 화면을 대조해 확인했으며 위에 적은 상태 칩 대비 조정 외에 남은 주요 시각적 불일치는 없습니다. 지도 지형·장소 수·저장자 이름은 실제 데이터에 따라 달라집니다. iPhone Safari와 홈 화면 앱에서의 실제 키보드·공유 단축어 실행은 별도 실기기 확인이 필요합니다.

추가 마이그레이션은 기존 장소와 저장자 기록을 보존하며, 검증 전용 보드는 사용 후 정리합니다. 검증 과정에서 실제 커플의 PIN은 변경하지 않습니다. 배포 후 아직 PIN이 없는 보드만 기존 지도 주소로 최초 설정을 진행하고, 이미 설정한 보드는 기존 PIN을 사용합니다.


## 삭제한 장소와 분석 사용 한도 (2026-10-24)

`supabase/migrations/006_place_trash.sql`을 적용한 뒤 앱을 배포합니다. 기존 데이터에 삭제 여부 열을 추가하고 관련 RPC만 교체합니다.

- 장소 삭제는 설정 → 삭제한 장소로 이동합니다. 복구 시 메모·상태·저장자·원본 연결을 그대로 유지하며 새 장소 알림을 보내지 않습니다. 보관 기한은 없습니다.
- 설정에서 영구 삭제를 확인하면 장소 DB 행과 연결 기록을 삭제합니다. 공용 원본 게시물은 유지합니다. 이미 복구되거나 다시 삭제된 장소는 오래된 목록으로 영구 삭제할 수 없습니다.
- 삭제한 장소를 같은 링크나 직접 검색으로 다시 추가하면 먼저 복구하도록 안내합니다. 영구 삭제 후에는 새로 등록할 수 있습니다.
- Gemini의 실제 거부 응답을 무료 일일 한도·일일 한도·일시 요청 제한·종류 미확인 한도로 구분하고, 확인 대기함에도 사유를 보존합니다. 일부 결과가 있으면 후보를 확인하도록 남깁니다. 남은 무료 횟수 사전 조회나 전체 처리 시간 제한은 구현하지 않았습니다.
- B01은 사용자 요청으로 제외했습니다. R06 제외와 R08–R12 보류는 유지합니다.
- 검증: 자동 테스트 433개, 타입 검사, 운영 빌드 및 합성 DB를 사용하는 로컬 운영 브라우저 점검 26개 통과. 모바일 390×844와 데스크톱 1440×900의 삭제·복구·영구 삭제·취소, 지도 제외/복귀, Gemini 사유의 대기함·확인 화면·응답 복구를 확인했습니다. Gemini 실제 한도를 소진시키는 운영 호출은 하지 않았습니다.


### 삭제 목록 페이지 후속 수정

설정의 삭제한 장소 항목은 삭제 기록 유무와 관계없이 항상 표시하며 `/settings/trash`로 이동합니다. 빈 목록도 독립 페이지로 표시하고 뒤로가기는 설정으로 돌아갑니다. 복구 API가 반환한 서버 확인 장소를 지도·목록·기기 캐시에 즉시 반영해 전체 목록 갱신을 기다리지 않게 했습니다. 관련 테스트 52개, 타입 검사·운영 빌드 및 모바일/데스크톱 브라우저 점검 31개를 통과했습니다. 브라우저에서는 목록 조회를 의도적으로 보류하고도 복구 장소가 먼저 나타나는 것을 확인했습니다.


### 축소 지도 핀 통일

메인 지도의 집계 단계(카카오 레벨 4 이상)에서는 권역에 장소가 1개뿐이거나 권역 조회 중이어도 숫자 집계핀을 사용합니다. 상호명 핀은 레벨 3 이하로 확대했을 때 표시합니다. 단일 집계핀도 누르면 확대되며, 상세 위치 미리보기는 상호명 핀을 유지합니다. 관련 테스트 36개·운영 빌드·모바일/데스크톱 브라우저 점검 22개를 통과했습니다.


### 모바일 등록·탐색 후속 개선

- 복구는 삭제 목록에서 계속 진행합니다. 알림의 ‘장소 보기’와 이 화면에서 복구한 항목별 링크를 눌렀을 때만 지도로 이동하며, 필요한 경우 필터를 해제하고 해당 카드로 이동합니다.
- 통합 검색은 저장 결과 상위 3개와 더 보기를 제공하고, 새 검색 결과도 다음 페이지를 조회할 수 있습니다. 다음 페이지에서 고른 장소도 서버가 같은 검색어·페이지를 다시 조회해 검증합니다. 삭제한 검색 결과를 즉시 복구하는 기능(개선안 8)은 보류합니다.
- 등록 방식은 인스타 주소와 직접 검색 두 가지입니다. 캡션 붙여넣기·스크린샷 업로드는 화면에서 제거했고, 서버도 새 업로드 요청을 거절합니다. 게시물의 자동 내용 수집과 기존 기록은 유지합니다.
- 확인 대기함은 추정 장소명·등록자·날짜·필요 행동을 표시합니다. 공통 Gemini 오류는 사유별 한 번만 짧게 안내합니다.


이번 모바일 후속 검증은 자동 테스트 451개·타입 검사·운영 빌드, 모바일 390×844·320×568 브라우저 점검 53개를 통과했습니다. 실제 앱 API와 합성 Supabase·카카오·Gemini 응답을 연결해 다음 페이지 선택 저장, 조회를 지연시킨 상태의 연속 복구 3개, 필터 밖 복구 장소 보기, 단일 숫자 핀의 한 번 터치, 한도별 대안 우선순위, 실패한 재분석 뒤 최신 세션 재확보, 공통 오류 요약과 작은 화면의 첫 항목 표시를 확인했습니다. 실제 iPhone 키보드·실제 지도 타일·운영 Gemini 한도 소진을 새로 시험하지는 않았습니다.

검색 페이지 처리의 기준: [카카오 키워드 장소 검색 공식 문서](https://developers.kakao.com/docs/ko/local/dev-guide#search-by-keyword).

### 메모 알림·새 장소 표시·PIN 화면 (2026-10-26)

배포 전 Supabase SQL Editor에서 `supabase/migrations/007_memo_push.sql`을 적용합니다. 기존 006까지 적용된 DB가 대상이며, 기존 VAPID 키와 기기 구독은 그대로 사용합니다. 새 환경변수나 알림 권한 재요청은 필요하지 않습니다.

2026-10-26(한국 시간) 운영 DB에 007 적용을 확인했습니다. `place_push_events.event_kind`·`memo_version` 컬럼, `event_kind`를 반환하는 `dm_claim_push_deliveries`, `memo_changed`를 반환하는 `dm_patch_place`가 모두 존재합니다. 008은 아직 적용 전입니다.

- 메모가 실제로 바뀐 경우 저장과 알림 기록을 한 트랜잭션으로 처리하고, 저장 성공 직후 기존 발송기를 실행합니다. 상대방의 유효한 구독 기기만 대상이며, 동일 내용·충돌·실패에는 알림을 추가하지 않습니다. 빈 내용으로 지우는 것은 저장만 하고 알리지 않습니다(008). 알림에는 작성자와 장소명만 담고 메모 본문은 넣지 않습니다. 기존 예약 작업이 실패한 발송을 재시도하며 OS의 실제 표시 시점은 별개입니다.
- 최초 등록 후 24시간 동안 이름 핀·장소 카드·리스트에 `NEW`를 표시합니다. 중복 저장이나 복구는 등록 시각을 갱신하지 않습니다. 앱을 열어 둔 경우에도 만료 시 표시를 제거합니다.
- 저장 후 지도 복귀는 카카오 레벨 3까지 확대해 상호명 핀을 표시합니다. 일반 축소 지도의 집계 규칙은 유지합니다.
- 모바일 PIN 화면은 입력 포커스 즉시 작게 배치하고 키보드의 보이는 높이를 따라갑니다. 확인 버튼·기억하기를 누르는 동안 배치를 유지하며 PIN은 계속 가립니다.
- 기기 잠금 성공 시 입장 화면으로 바로 전환해 기존 경로의 지도 로딩 안내가 노출되지 않도록 했습니다.
- 검증: 자동 테스트 460개, 타입 검사 포함 운영 빌드. 합성 DB·지도 SDK를 쓰는 모바일/데스크톱 브라우저에서 저장 직후 이름 핀, NEW, 잠금·재입장 및 입력 전 키보드 높이 변경을 확인했습니다. 운영 푸시는 발송하지 않았으며 실제 iPhone PWA 키보드와 푸시 수신은 배포 후 실기기 확인 항목입니다.

#### 메모 알림 보완 (008)

007 적용 DB에 `supabase/migrations/008_memo_push_fixes.sql`을 실행한 뒤 앱을 배포합니다. 다시 실행해도 안전합니다.

- 메모를 빈 내용으로 지우면 알림을 만들지 않습니다. 다시 쓰면 `메모를 남겼어요`로 알립니다.
- 알림 tag를 장소 단위(`place-<장소 id>`)로 바꿔 같은 장소의 알림은 최신 1건으로 교체되며, 교체 때도 다시 울리도록 `renotify`를 켰습니다.
