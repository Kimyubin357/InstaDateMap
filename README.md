# 데이트맵

인스타에서 발견한 곳과 직접 찾은 장소를 둘만의 지도에 모으는 커플용 앱입니다. 사귄 날짜로 만든 여섯 자리 PIN으로 열고, 지도와 리스트로 함께 살펴봅니다.

## 이번 버전에 들어 있는 기능

- 날짜에서 만든 YYMMDD PIN, 기기 기억하기, 두 사람 이름 선택, PIN 변경과 기기 잠금
- 카카오 지도·리스트 전환, 상호·주소·메모 검색, 상태·분류 필터, 최근 저장·가까운순
- 인스타 캡션·위치 태그·스크린샷에서 장소 추출, 여러 장소·지점 확인, 직접 검색
- 인스타 링크 없이 카카오 장소 검색으로 바로 저장
- 중복 병합, 둘 다 저장함, 상태 네 종류, 메모, 주소 복사, 카카오맵 열기
- 실제 처리 단계를 표시하는 링크 저장 진행 화면, 실패한 링크 확인 대기함

영상 속 자막·음성 추출과 기존 DM 가져오기는 아직 구현하지 않았습니다.

## 기존 버전에서 업데이트

1. Supabase SQL Editor에서 `supabase/migrations/002_couple_access.sql`을 실행합니다. 기존 장소·메모·상태·원본 연결을 보존하고 저장자 기록을 이관합니다. 다시 실행해도 중복되지 않습니다.
2. 앱을 빌드하고 배포합니다. Git 자동 배포를 쓴다면 마이그레이션을 먼저 적용하세요.
3. **처음 한 번만** 기존 `?t=보드토큰` 주소로 엽니다. 최초 설정 권한을 확인한 뒤 주소에서 토큰을 제거합니다.
4. 사귄 날짜와 두 사람의 이름을 입력하고, 날짜의 YYMMDD 여섯 자리를 한 번 더 확인합니다. 기존 저장자 이름은 그대로 사용합니다.
5. 각 기기에서 본인의 이름을 고릅니다. 이후에는 토큰 없는 기본 주소를 홈 화면에 추가하세요.

PIN 설정 후 기존 토큰은 폐기됩니다. 예전 주소나 `x-board-token`으로 데이터에 접근할 수 없습니다. 실제 날짜와 PIN을 코드·환경 변수·Git에 넣지 마세요.

### iPhone 홈 화면 앱

Safari의 공유 → 홈 화면에 추가에서 **웹 앱으로 열기**를 켭니다. `/enter`에서 추가해도 앱은 항상 기본 지도 주소(`/`)로 시작하며 PIN·이름 선택·지도·저장·설정을 같은 앱 범위로 사용합니다. 입장 후 이동에는 앱 내부 화면 전환을 사용합니다.

PIN 화면에는 없던 주소 표시와 Safari 버튼이 지도에서 나타난다면, 이 PWA 수정 버전을 배포한 뒤 확인해 주세요. 기존 홈 화면 아이콘이 이전 설치 정보를 유지하는 경우 Safari에서 기본 주소를 열어 새 아이콘을 추가한 뒤 확인합니다. 실제 iPhone의 도구막대 표시 여부는 실기기 확인이 필요합니다.

## 새로 설치

1. Supabase 프로젝트를 만들고 `supabase/schema.sql`, `supabase/migrations/002_couple_access.sql` 순서로 실행합니다. 초기 스키마에서 받은 보드 토큰은 최초 설정에만 씁니다.
2. `.env.example`을 `.env.local`로 복사하고 다음 값을 채웁니다.
   - `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`: 서버 전용 Supabase 키
   - `KAKAO_REST_API_KEY`, `NEXT_PUBLIC_KAKAO_JS_KEY`: 서버 검색과 브라우저 지도용 키
   - `GEMINI_API_KEY`: 기본 장소 추출 모델. Anthropic 사용 시 `LLM_PROVIDER=anthropic`, `ANTHROPIC_API_KEY` 설정
   - `APP_BASE_URL`: 배포 주소
   - `APP_BOARD_ID`: 보드가 여러 개일 때 사용할 보드 UUID. 커플 하나가 쓰는 기본 구성에서는 생략 가능
3. 카카오 디벨로퍼스에서 카카오맵 사용을 설정하고 배포 주소와 `http://localhost:3000`을 Web 도메인에 등록합니다.
4. `npm install`, `npm run dev`로 실행한 뒤 기존 버전 업데이트의 3~5단계처럼 최초 PIN을 설정합니다.

```sh
npm run dev        # http://localhost:3000
npm test           # 추출·저장·API·인증·스트림 회귀 테스트
npm run typecheck
npm run build
npm run start
```

## 인스타 공유 단축어

예전의 API 직접 호출 단축어 대신 **저장 화면을 여는 방식**을 사용합니다. 단축어 앱에서:

1. 공유 시트 입력으로 URL과 텍스트를 받습니다.
2. 공유한 인스타 링크를 URL 인코딩합니다.
3. `https://배포주소/add?url=인코딩한링크`를 URL 열기로 엽니다.

기억된 기기는 바로 링크를 처리합니다. PIN 입력이나 이름 선택이 필요하면 원래 공유 링크를 유지한 채 해당 화면을 거칩니다. Safari와 홈 화면 웹 앱의 저장 공간이 분리된 경우 각각 처음 한 번 PIN을 입력해야 할 수 있습니다.

스크린샷은 장소 저장 화면에서 직접 올립니다. 캡션을 읽지 못하면 캡션 붙여넣기·스크린샷·직접 검색으로 이어갈 수 있습니다.

## PIN을 잊었을 때

서버 관리자가 이 프로젝트의 환경 변수를 설정한 터미널에서 `npm run pin:reset`을 실행합니다. 새 PIN을 숨겨 입력받고, 모든 기기의 세션을 만료시킵니다. 보드가 여러 개라면 `APP_BOARD_ID`를 지정하거나 `npm run pin:reset -- --board=보드UUID`를 사용합니다. PIN을 명령 인수로 전달하지 않습니다.

## 데이터와 접근 방식

- PIN은 salt가 있는 scrypt 해시로만 저장합니다. 세션 식별자는 HttpOnly 쿠키, DB에는 그 식별자의 해시만 저장합니다.
- 기기 기억하기는 90일, 선택하지 않으면 브라우저 세션 쿠키와 서버 기준 12시간 만료를 사용합니다.
- PIN 시도 제한은 DB에서 동시 요청을 포함해 집계합니다. 15분 동안 IP별 5회, 보드 전체 30회 실패 시 15분 제한하며 열린 정상 세션은 유지합니다.
- 모든 테이블에 RLS를 적용하고 서버의 service role만 접근합니다. 변경 요청에는 Origin 검증을 적용합니다.
- `place_saves`는 링크 유무와 무관하게 저장자를 기록하고, `source_places`는 인스타 원본 연결을 유지합니다. 장소·저장자·원본 연결은 SQL 함수의 한 트랜잭션으로 저장합니다.
- 인증 조회와 지도 목록에는 `no-store`를 사용합니다. DB 오류를 빈 지도나 저장 성공으로 처리하지 않습니다.
- 인스타 사진·영상은 저장하지 않으며 원본은 공식 임베드로 펼쳐 봅니다.

## 추출 모듈 추가

`src/lib/extract/types.ts`의 `ExtractorModule` 규격을 구현하고 `router.ts`의 `MODULES`에 등록합니다. 가벼운 모듈은 함께 실행하고, 무거운 모듈은 앞 결과가 부족할 때 실행합니다. 사용자가 직접 올린 스크린샷은 항상 분석합니다. 새 모듈 이름은 DB 체크 제약에도 추가해야 합니다.

## 이번 변경의 검증 기록

- 기존 55개 회귀 검증을 유지하며 총 82개 자동 테스트 통과. 타입 검사와 Next.js 운영 빌드 통과. 추가된 PWA 검증은 시작 주소와 앱 이동 범위를 확인합니다.
- 실제 Supabase·카카오·장소 추출 API와 별도 임시 보드로 최초 설정 → 두 기기 입장·이름 선택 → 공유 링크·직접 검색 → 중복 병합 → 메모·상태 → PIN 변경을 확인했습니다. 공유한 인스타 릴스는 도나스데이 본점으로 저장되고 곧바로 목록에 나타났습니다.
- 잘못된 PIN 5회 후 IP 제한, 동시 40건 중 보드 제한 30건 적용, 정상 세션 유지, 서버 만료, 기기 잠금, 외부 Origin 및 폐기된 토큰 거절을 확인했습니다. 트랜잭션 오류는 고아 장소를 남기지 않았습니다.
- 운영 모드에서 삭제 후 같은 링크 재저장, 실패 후 재시도, 메모·상태 보존, 확인 대기함의 직접 검색·확인 후 저장을 확인했습니다.
- 전용 Browser 플러그인이 제공되지 않아 Playwright와 설치된 Chrome으로 검증했습니다. 390×844, 1440×900 및 높이 560 화면에서 검색·뒤로가기·포커스 복귀·Escape·위치 권한 거절·스크롤을 확인했습니다. 숫자 키보드 속성과 PIN 표시 전환도 확인했습니다.

승인된 PIN 시안과 최신 브라우저 캡처를 각각 열어 다음을 비교했습니다. 시안은 휴대폰 여러 대를 합친 이미지이므로 개별 화면은 요청한 390×844 크기를 기준으로 검증했습니다.

시안의 핵심 구성과 실제 화면을 대조해 확인했으며 위에 적은 상태 칩 대비 조정 외에 남은 주요 시각적 불일치는 없습니다. 지도 지형·장소 수·저장자 이름은 실제 데이터에 따라 달라집니다. iPhone Safari와 홈 화면 앱에서의 실제 키보드·공유 단축어 실행은 별도 실기기 확인이 필요합니다.

연결된 DB에는 추가 마이그레이션을 적용했고 임시 검증 보드는 삭제했습니다. 기존 두 장소와 저장자 기록의 보존을 확인했으며, 기존 보드의 실제 날짜와 PIN은 설정하지 않았습니다. 이번 코드의 Git 푸시와 배포는 별도이며, 배포 후 기존 지도 주소로 최초 설정을 한 번 진행하면 됩니다.
