설계 요지

  1. 네 영역, 정해진 쌓기 순서. ①검색·필터·설정 ②상태 칩(확인 대기·새 장소·필터·모음) ③장소 카드 자리(미리보기·묶음 목록·저장 결과) ④이동·추가(지도/리스트, ＋). 세로는 ①② 위 / ③④ 아래, 가로는 ①③ 왼쪽 열 / ② 지도 위 가운데 / ④ 오른쪽 열 / 알림은 지도 아래 가운데. 각 영역이 자기 줄 안에서만 쌓여서 카드·알림·확인 대기가 서로 덮을 수 없습니다. 지도는 이 영역들을 뺀 남은 사각형에 맞춰 범위를 잡습니다.
  2. 가로는 따로 배치. 가로에서 높이가 가장 귀하므로 카드·목록·상세·필터를 왼쪽 열로 보내고, 지도/리스트 전환·내 위치·전체·＋는 오른손 엄지가 닿는 오른쪽 열에 세웁니다. 모든 것이 노치 59px 안쪽과 홈 표시줄 위에 있습니다.
  3. 묶음 = 지역 이름표. 숫자 원 대신 “성수동 12 / 가고 싶음 7”. 1곳은 절대 숫자가 되지 않고, 동네 단계부터는 묶지 않습니다. 묶음을 누르면 범위 맞춤과 목록이 동시에 → 축소 상태에서도 탭 2번이면 미리보기.
  4. 등록 직후·상대의 새 장소 = 결과 카드 + 집중 표시. 저장한 곳 전부에 범위를 맞추고, 그 장소들은 묶지 않으며(여러 곳이면 ①②③ 번호), 나머지는 흐리게 둡니다. 카드 자체가 “저장했어요” 알림이고 그 안에서 상태·메모를 바로 고칩니다.
  5. 자주 하는 편집은 엄지 자리. 상태 4종은 상세 아래 고정 줄과 저장 결과 카드 안에 있고, 누르는 즉시 저장되며 결과는 바로 위 한 줄에서 알려 줍니다. 필터의 상태 버튼은 지도 기호와 같은 모양이라 범례를 겸합니다.

5장 질문에 대한 답

숫자만 보고 “무엇이 몇 곳”인지 알 수 있나요? 1곳일 때도 숫자가 필요한가요? 숫자만 두지 않습니다. 묶음은 지역 이름 + 곳 수(첫 줄)와 “가고 싶음 n”(둘째 줄, 전부면 “모두 가고 싶음”, 없으면 “모두 다녀옴”)를 함께 보여 줍니다. 1곳은 숫자가 필요 없으므로 묶지 않고 상태 기호(여유가 있으면 이름까지)로 둡니다. 의미가 드러나지 않던 “다녀온 비율” 진행 링은 없앴습니다.
묶음을 누르면 확대인가요, 목록인가요? 둘 다, 동시에 합니다. 기본 동작은 묶음 범위로 한 번에 맞추기 + 같은 순간 목록 열기(세로는 아래 42% 높이, 가로는 왼쪽 열)입니다. 2단계씩 반복해서 확대하던 동작은 없앴습니다. 목록은 새로 저장 → 하위 지역(구별) 또는 상태(가고 싶음 / 다녀온 곳) 순서이고, 구 제목은 “그 구만 확대” 버튼입니다. 목록을 닫으면 지도만 남습니다. → S2 2·3번
상태(가고 싶음 대 다녀옴)와 “새로 등록한 장소”가 축소 상태에서도 드러나야 하나요? 네. 가고 싶음은 묶음 이름표 둘째 줄의 개수로 드러나고, 다녀옴 쪽은 “전체 − 가고 싶음”으로 읽힙니다(4종 전부를 축소 상태에 넣으면 읽기 어려워짐). 1곳 표시물은 모양으로 4종(빈 원·체크·하트·점선 원)이 구분됩니다. NEW는 묶음의 “NEW n” 꼬리표로 남고, 다른 묶음과 겹치지 않으면 따로 떨어진 표시물(N 배지)로 남습니다. → 묶음 단계 1·2번
여러 곳을 한 번에 저장한 직후에는? 전부 범위 맞추기를 기본으로 합니다. 각 장소에 링크 속 순서대로 ①②③을 붙이고, 같은 번호의 결과 목록 카드를 띄웁니다. 번호 표시는 어떤 단계에서도 묶이지 않고, 겹치는 묶음 이름표는 비켜서 점선으로 원래 자리를 가리킵니다. 차례로 보기는 미리보기의 이전/다음이 그 3곳 안에서만 돌면서 지도를 따라가게 합니다. → S4
이름표가 겹칠 때 묶음 대신 쓸 방법은? 동네·가게 단계에서는 묶지 않고 세 가지를 씁니다. (a) 우선순위 이름표: 선택 → 방금 저장 → NEW → 가고 싶음 → 또 갈래 → 다녀옴 → 별로 순으로, 겹치지 않는 것만 이름을 붙이고 나머지는 기호만 둡니다. (b) 펼치기: 기호끼리 겹치면 둘레로 벌리고 실제 위치를 점선으로 잇습니다. (c) 이름 줄임: 동네 9자 / 가게 14자에서 줄이고, 전체 이름은 미리보기·상세에서 봅니다. 묶음은 넓은 지역·구 단계에서, 표시물 터치 영역(44px)이 8px 안으로 붙을 때만 씁니다.
서울 전체 → 동네 → 가게로 확대하는 동안 같은 장소를 따라갈 수 있나요? 네. ① 이름표가 지역 이름이라 “서울 → 성수동 → 기호 → 이름”이 말로 이어지고, ② 선택한 장소는 어떤 단계에서도 묶이지 않고 따로 크게 남으며(겹치는 이름표는 비켜남), ③ 묶음 탭이 범위 맞춤 한 번이라 중간 단계가 적습니다. → 묶음 단계 5~8번

사용한 지침 (UI/UX Pro Max)

  • touch-target-size, touch-spacing: 모든 버튼·칩·목록 행 44px 이상, 8px 이상 간격 — 페이지마다 자동 검사.
  • safe-area-awareness, Safe-area compliance, System bar clearance, Adaptive gutters by breakpoint: 노치·홈 표시줄 안쪽 배치, 가로 좌우 여백.
  • orientation-support, fixed-element-offset, “Fixed Positioning — Account for safe areas and other fixed elements / Don't stack multiple fixed elements carelessly”: 고정 요소를 영역별로 쌓는 구조와 지도 범위 계산.
  • primary-action: ＋ 장소 추가 하나만 주요 버튼(0곳 안내도 새 버튼을 만들지 않음).
  • gesture-alternative, gesture-conflicts, standard-gestures: 카드 밀기에는 이전/다음 버튼, 지도 기본 제스처는 바꾸지 않음.
  • sheet-dismiss-confirm, confirmation-dialogs, destructive-emphasis: 저장 안 한 메모 확인, 삭제 확인(점선으로 분리).
  • toast-accessibility, toast-dismiss, success-feedback, error-recovery, empty-states, undo-support: 알림은 포커스를 뺏지 않고 4초, 결과는 그 자리 한 줄, 실패엔 다시 시도, 필터 해제엔 되돌리기.
  • color-not-only, truncation-strategy, nav-label-icon, aria-labels: 상태는 모양+글자, 줄인 이름은 상세에서 전체, 아이콘 버튼에 글자·접근성 이름.
  • 지침에 없는 지도 표시물 묶음·펼치기·이름표 우선순위는 지도 UX 일반 지식으로 설계했습니다.

못 한 것 · 알려진 한계

  • 568×320 가로: 왼쪽 열(236px)과 오른쪽 열을 빼면 카드가 열렸을 때 지도 띠가 약 120px 폭입니다. 미리보기 중에는 지도를 동네 단계 아래로 줄이지 않는 규칙으로 보완했지만 좁습니다. 칩이 2개 이상이면 2줄로 쌓이고, 선택한 장소 이름표가 7자로 줄거나 빠질 수 있습니다(번호 표시는 목록 번호로 짝을 맞춤).
  • 320×568 세로: 카드가 열려 있는 동안 아래 이동 줄(지도/리스트·＋)을 숨깁니다. 카드를 닫으면 돌아옵니다. 다른 크기에서는 늘 보입니다.
  • 지도 표시물의 터치 간격: 동네 단계에서 기호 사이가 30px 안팎이라 44px 터치 영역끼리는 겹칠 수 있습니다(화면 버튼은 모두 검사 통과). 손가락 근처에 표시물이 둘 이상이면 그 자리 목록을 띄우는 규칙을 가정했지만 프레임으로 그리지는 않았습니다.
  • 지도 표시물·이름표는 카드·버튼 아래로 지나갈 수 있습니다(일반 지도 동작). 범위 맞춤과 이름표 위치는 가려지지 않는 사각형 안으로 계산합니다.
