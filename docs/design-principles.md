# 데이트맵 디자인 철칙

이 문서는 데이트맵의 새 화면·컴포넌트·버튼을 만들거나 기존 UI를 수정할 때 먼저 읽는 기준입니다. 사용자가 정한 패브릭 실크스크린 테마와 기존 조작 방식을 이어갑니다. 현재 화면에 오래된 스타일이 남아 있으면 그대로 복제하지 말고 이 기준과 아래 기준 컴포넌트를 함께 확인합니다.

## 1. 같은 앱으로 보이게 만들기

- 바탕은 따뜻한 아이보리 원단, 카드·입력칸·보조 버튼은 밝은 크림 원단을 사용합니다. 박음질 같은 가는 점선과 절제된 인쇄 그림자로 경계를 만듭니다.
- 주요 실행은 붉은 잉크, 선택 상태와 보조 동작은 짙은 초록, 본문은 짙은 갈색을 기본으로 합니다. 상태별 색과 인스타 원본 버튼처럼 이미 합의한 예외는 유지합니다.
- 새 기능에도 기존 색·서체·아이콘·재질을 적용합니다. 앱과 관계없는 범용 대시보드 카드, 유리 효과, 네온 색, 과도한 그라데이션이나 큰 그림자를 임의로 도입하지 않습니다.
- 리스트·설정·검색 결과는 열린 행과 구분선으로 연결합니다. 짧은 내용마다 카드를 추가하지 않습니다. 기존 지도 타일에는 색 보정이나 원단·노이즈 오버레이를 씌우지 않습니다.

## 2. 공통 토큰과 글씨

값은 `src/app/globals.css`의 공통 토큰을 재사용하고, 테마 표현은 `src/app/fabric-theme.css`에서 확인합니다. 아래 표는 현재 기준값이며 같은 색을 새 이름이나 하드코딩 값으로 중복 정의하지 않습니다.

| 용도 | 토큰 | 현재 값 |
| --- | --- | --- |
| 아이보리 원단 바탕 | `--paper` | `#f4efdf` |
| 밝은 크림 표면 | `--cream` | `#fbf6e8` |
| 본문 / 보조 글씨 | `--ink` / `--ink-soft` | `#382f25` / `#756b5b` |
| 따뜻한 박음질·구분선 | `--line` | `#d5c8ab` |
| 주요 실행 / 진한 붉은 글씨 | `--accent` / `--accent-ink` | `#b92b25` / `#a52620` |
| 보조·선택의 초록 잉크 | `--forest` | `#244b37` |
| 원단 / 인쇄 질감 | `--weave` / `--grain` | 기존 SVG 타일 |
| 작은 인쇄 그림자 | `--print-shadow` | `0 2px 0 #382f2512, 0 4px 12px #382f2510` |

- 앱 글씨는 로컬 온글잎 박다현체(`--font-dahyun`)의 정규 굵기 **400**을 사용합니다. 공통 선언은 `src/lib/app-font.ts`에 있으며 일반 화면과 전역 오류 화면이 함께 사용합니다. 현재 `next/font/local`의 125% 높이 보정과 `font-synthesis:none`을 유지하며 가짜 굵기나 다른 손글씨체를 추가하지 않습니다.
- 제목·본문·주소·버튼의 크기는 주변 컴포넌트와 비교해 정합니다. 글자가 작다는 이유만으로 굵기를 올리지 않습니다. 긴 한글 장소명·주소·메모의 줄바꿈과 잘림을 확인합니다.
- 아이콘은 `src/components/Icon.tsx`의 기존 SVG 체계를 사용합니다. 선 굵기와 모양을 맞추고, 같은 기능에 새 아이콘 라이브러리나 이모지를 섞지 않습니다.

## 3. 버튼과 장소 상세 닫기

장소 상세의 **접힌 상태와 중간 높이의 닫기 X는 작은 지도 위 ‘지도에서 보기’ 버튼(`.preview-map-button`)을 재질 기준으로 삼습니다.** 지도에서 열었든 리스트에서 열었든 같은 닫기 버튼을 사용합니다. 지도·리스트 상세의 전체 화면에서는 배경·점선·그림자 없이 X만 표시하고, 왼쪽의 뒤로 가기는 중간 높이로 돌아갑니다.

- 크림 바탕과 원단 질감: `background:var(--cream) var(--weave)`.
- 가는 따뜻한 점선: `border:1px dashed var(--line)`.
- 절제된 인쇄 그림자: `box-shadow:var(--print-shadow)`.
- 글씨·기호는 기존 잉크색과 SVG 아이콘을 사용합니다. 흰색 반투명 유리 원, 광택, 별도의 짙은 그림자는 닫기 버튼의 기준이 아닙니다.
- 시각적인 X 크기와 누르는 영역을 구분합니다. 작은 X·방향 아이콘은 보통 **16~18px**, 실제 터치 영역은 **최소 44×44 CSS px**를 확보합니다. 다른 버튼의 크기를 정할 때도 같은 구분을 적용합니다.
- 접힌 지도 시트의 닫기 배경은 32px, 실제 터치 영역은 44px로 구분하고 장소명·상태와 수직 중앙을 맞춥니다. 지도·리스트 전체 화면의 상단 탐색 아이콘은 22px로 표시합니다. 지도·리스트의 일반 닫기와 지도 카드 닫기는 동일한 32px 원단 배경·18px X·44px 터치 영역을 사용합니다.
- 터치 영역을 넓혀도 장소명·카드·지도 조작을 덮지 않도록 실제 사각형과 간격을 측정합니다. 닫기 버튼 주변의 제목 여백도 함께 조정합니다.
- 기본·누름·키보드 포커스·비활성 상태를 함께 구현합니다. `:focus-visible`을 지우지 않고, `disabled`와 처리 중 안내를 실제 동작에 연결합니다. 토글은 `aria-pressed`, 아이콘만 있는 버튼은 한국어 접근성 이름을 제공합니다.
- 작은 버튼의 시각 스타일만 바꿀 때는 저장·삭제·메모 확인·드래그·포커스 복귀 동작을 유지합니다. 배경·점선·아이콘·상태 표현은 지도와 리스트에서 따로 갈라지지 않게 공통 규칙으로 둡니다.

### 지도·리스트 상세의 독립된 배치

- 지도 상세 최소: 장소명·상태·닫기와 하단 동작 버튼만 표시합니다. 중간: 주소·장소 정보·상태 선택까지 표시합니다. 높이는 고정 화면 비율 대신 제목 줄바꿈, 콘텐츠, 하단 safe-area를 실제 측정해 정합니다.
- 지도 상세 최대: 휴대폰 세로·가로 모두 보이는 화면 전체를 채웁니다. 모서리를 펴고 상단 safe-area 아래에 뒤로 가기·X를 둡니다. 짧은 가로 화면은 탐색 버튼과 제목을 한 줄로 배치합니다.
- 짧은 가로 화면에서는 중간 높이에 모든 내용을 억지로 넣지 않고 본문을 스크롤합니다. 하단 동작은 고정하고, 가려진 최소 상태의 본문에는 포커스가 들어가지 않아야 합니다.
- 본문 최상단에서 위로 밀면 한 단계 펼치고, 아래로 당기면 한 단계 접습니다. 최대 높이의 위 스크롤과 이미 스크롤된 본문·입력칸의 조작은 기본 스크롤을 유지합니다. 최소 높이에서 다시 아래로 당기면 닫습니다.
- 리스트 상세는 **작은 지도 → 장소명·상태 → 주소·정보 → 상태 선택 → 메모** 순서를 유지합니다. 폭 760px 미만에서 최소·중간 높이는 원본 `64d71b4`의 48%·63.5%를 그대로 유지합니다. 최대만 화면 전체를 채우고 뒤로 가기·배경 없는 X를 둡니다. 전체 화면 상태로 회전해도 페이지 형태를 유지합니다. 폭 760px 이상의 일반 상태는 원래의 520px 중앙 패널과 숨겨진 손잡이를 유지합니다. 지도 상세의 요약 높이 규칙을 리스트에 함께 적용하지 않습니다.
- `MapPlaceSheet.tsx`/`MapPlaceSheet.module.css`와 `ListPlaceSheet.tsx`/`ListPlaceSheet.module.css`가 각각 화면 순서와 배치를 담당합니다. `PlaceSheet.tsx`의 저장·삭제·초안 보호와 공통 정보, `Modal.tsx`의 제스처·접근성 및 원단·색 토큰은 재사용하되 한 화면의 배치 변경을 다른 화면에 전파하지 않습니다.
- 드래그 감지는 본문이나 제목 일부가 아니라 시트 전체 표면에 연결합니다. 손잡이 아래 여백·제목·본문 좌우 여백·하단 버튼 사이·하단 여백에서 시작한 터치도 처리합니다. 입력칸과 내부 스크롤 영역은 본래 조작을 유지합니다.
- 본문 최상단에서 시작한 위 스와이프만 높이를 올립니다. 본문이 스크롤된 상태와 최대 높이에서는 본문 스크롤이 우선이며, 고정 헤더·하단 여백의 스와이프도 같은 본문 스크롤로 전달합니다. 별도 손잡이의 직접 크기 조절은 유지합니다. 버튼 탭은 원래 동작하고, 스와이프 뒤의 우발적인 클릭만 차단합니다.
- 상세가 열린 동안 최소·중간·전체 화면 모두 배경 장소 카드를 숨깁니다. 상세가 완전히 닫히면 선택한 장소의 카드와 포커스를 복원합니다. 메모 초안은 단계 이동으로 사라지지 않아야 합니다.

## 4. 가로 화면부터 배치하기

**가로 모드 전체 리디자인은 아직 미완료입니다.** 다음 레이아웃 설계는 짧은 가로 화면부터 시작하며, 버튼 일부 수정이나 특정 화면 통과를 전체 과제 완료로 기록하지 않습니다. 현재 진행 상태와 전체 완료 기준은 [AGENTS.md](../AGENTS.md)를 따릅니다. 사용자가 승인한 작업 범위도 함께 지킵니다.

- 최소 확인 크기: **320×568, 568×320, 667×375, 844×390, 932×430**.
- 상하뿐 아니라 좌우 `safe-area-inset-*`를 반영합니다. 화면 방향을 강제로 고정해 겹침을 숨기지 않습니다.
- 폭이 넓다고 휴대폰 키보드가 없다고 가정하지 않습니다. 검색·PIN·메모 입력에서 실제 보이는 뷰포트와 스크롤 가능 영역을 확인합니다.
- 지도·검색·필터·카드·하단 탭·토스트·설정·시트가 서로 가리지 않아야 합니다. 정상 상태 외에 로딩·오류·빈 결과·긴 글씨·키보드가 열린 상태도 확인합니다.
- 버튼 클릭과 스크롤, 시트 열기·닫기, 키보드 포커스 이동을 실제 렌더링에서 검사합니다. 타입 검사나 스크린샷 한 장만으로 반응형 완료를 선언하지 않습니다.
- iPhone의 노치·시스템 키보드·홈 화면 앱 동작은 브라우저 모의 검증과 구분해 기록합니다.

## 5. 안내·오류·복구도 같은 디자인으로

- 사용자 안내는 자연스러운 한국어로 현재 상태와 다음 행동을 설명합니다. DB·카카오·브라우저 원문 오류, 환경 변수·마이그레이션 등 운영자용 설명은 화면에 노출하지 않습니다.
- 성공은 기존 토스트, 확인이 필요한 행동은 기존 다이얼로그를 우선 사용합니다. 새로운 알림 모양을 매번 만들지 않습니다.
- 화면 오류·없는 주소에서도 동일한 원단·서체·버튼을 사용하고 ‘다시 시도’, ‘우리 지도’처럼 실제 가능한 복구 동작을 제공합니다.
- 네트워크 응답을 받지 못한 일을 저장 실패로 단정하거나, 확인되지 않은 저장을 성공으로 표시하지 않습니다. 기존 확인·재시도 흐름을 유지합니다.

## 6. 에셋과 변경 기록

- 사용자가 제공한 원본은 보관하고 비율·투명도·캐릭터를 유지합니다. 원본을 덮어쓰지 않습니다.
- **허가받지 않은 용도로 원본 에셋을 재사용하지 않습니다.** 입장 그림을 빈 화면이나 오류 화면에 옮기거나 캐릭터를 임의로 새 버튼에 쓰지 않습니다. 용도별 승인·대기 상태는 [테마·에셋 문서](visual-theme.md)를 확인합니다.
- 레퍼런스가 있으면 해당 요소의 재질·선·크기·간격을 현재 화면과 비교합니다. 일반적인 ‘예쁜 UI’를 새로 상상해 기존 앱을 바꾸지 않습니다.
- 변경한 범위, 확인한 화면 크기·상태, 남은 실기기 검증을 기록합니다. 기존 사용자 제외·보류 결정을 새 디자인 작업에서 임의로 되살리지 않습니다.
