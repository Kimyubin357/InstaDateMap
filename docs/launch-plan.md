# 공개 배포 확장 계획: 계정·폴더·멤버·장소 정보

2026-11-24 작성. 둘만 쓰던 데이트맵을 **혼자 / 둘이 / 친구들과** 쓰는 공개 서비스로 넓히기 위한 전체 계획입니다. 이 문서 작성 과정에서 코드는 수정하지 않았습니다.

- 사용자 결정: 약관·비공식 데이터 수집 같은 위험은 **일단 고려하지 않고** 기능을 계획한다(2026-11-24). 위험 항목은 [위험 메모](#위험-메모-지금은-보류)에만 기록한다.
- 사용자 결정(2026-11-24): **앱은 PWA로 유지**한다. 네이티브 앱 전환과 단축어 공유 방식 개선은 프로젝트 전체가 끝난 뒤 다시 확인한다.
- 기존 필수 과제는 그대로 유효하다. 새 화면은 [AGENTS.md](../AGENTS.md)의 **가로 모드부터 설계**하고 [디자인 철칙](design-principles.md)을 따른다. 장소 등록 흐름은 [장소 등록 재설계](place-registration-redesign.md)와 함께 다룬다.
- 지도 도구(내 위치·전체 보기·하단 탭·+ 버튼)는 기존 그대로 유지한다.

## 1. 확정한 제품 방향 (사용자 결정)

| 항목 | 결정 |
| --- | --- |
| 가입 | SNS 로그인: **카카오, 구글** 먼저. 네이버·애플은 나중에 확장 |
| 기본 폴더 | 가입하면 1인용 **"내 장소"** 폴더 1개가 자동으로 생긴다 |
| 폴더 개수 | 폴더를 추가할 수 있고, **전부 지워 0개가 되어도 된다** |
| 멤버 | 폴더에 **링크로 초대**. 기술 상한 10명, **운영 상한 8명** |
| 장소 이동 | 장소(가게)를 **폴더 단위로 옮길 수 있다** |
| 장소 정보 | 네이버 플레이스의 **사진(최대 5장)·메뉴/가격·영업시간·전화번호**를 가져온다 |
| 예약 | **캐치테이블에 입점한 가게만** 버튼을 보여주고, 누르면 **그 매장 페이지로 바로** 연결한다 |

## 2. 기본값으로 정한 것 (바꿀 수 있음)

사용자가 따로 정하지 않은 항목은 아래 기본값으로 설계합니다. 바꾸려면 이 표만 고치면 됩니다.

| 항목 | 기본값 | 이유 |
| --- | --- | --- |
| 지도에 폴더 표시 | 폴더 하나를 골라 보기 + **"전체 보기"**(폴더 색으로 구분) | 폴더가 여러 개여도 한눈에 보기 |
| 기존 "모음" 기능 | **폴더 안의 분류(태그)로 유지** | 폴더 = 공유 단위, 모음 = 폴더 안 정리 |
| 옮기기 / 복사 | **옮기기 + 담기(복사)** 둘 다 | 공유 폴더에서 옮기면 다른 멤버 지도에서도 사라지므로 복사가 필요 |
| 같은 가게가 옮길 폴더에 이미 있을 때 | 하나로 합치고, 메모는 둘 다 보존, 상태는 옮겨 받는 폴더 기준 | 데이터 유실 방지 |
| 폴더 권한 | 만든 사람 = **방장**: 이름 수정·초대·내보내기·삭제. 멤버: 장소 저장·수정·나가기 | 친구 폴더에서 실수로 전체 삭제 방지 |
| 방장이 나갈 때 | 가장 오래된 멤버에게 방장 넘김. 혼자면 폴더 삭제 | 주인 없는 폴더 방지 |
| 초대 링크 | 7일 만료, 방장이 다시 만들거나 끊을 수 있음 | 링크 유출 대비 |
| 폴더 0개 상태 | 지도는 빈 화면 + "폴더 만들기". 장소를 저장할 때 폴더가 없으면 그 자리에서 만들기 | 0개 허용 결정 반영 |
| 기존 우리 둘 데이터 | 첫 공유 폴더로 옮기고, 두 사람이 로그인하면 기존 이름에 계정을 연결 | 메모·저장자 기록 유지 |
| 날짜 PIN | **없앤다** (원하면 나중에 "앱 잠금"으로 부활) | 계정 로그인으로 대체 |
| 회원 탈퇴 | 개인 폴더는 삭제. 공유 폴더에 저장한 장소는 남기고 이름을 "탈퇴한 사용자"로 표시 | 다른 멤버의 지도를 지키기 |

## 3. 전체 기능 목록

### A. 계정
- 카카오·구글 로그인, 로그아웃, 기기별 로그인 유지
- 프로필: 닉네임·사진(SNS에서 가져오고 수정 가능)
- 회원 탈퇴와 데이터 처리
- 나중에: 네이버·애플 로그인

### B. 폴더
- 가입 시 "내 장소" 자동 생성
- 폴더 만들기·이름/색/아이콘 수정·삭제, 0개 허용
- 폴더 전환 UI(검색 줄 근처의 폴더 선택) + 전체 보기
- 마지막으로 본 폴더 기억

### C. 멤버
- 초대 링크 만들기·복사·카카오톡 공유·끊기
- 초대 받은 사람: 링크 → 로그인 → 폴더 미리보기 → 참여
- 멤버 목록, 내보내기, 나가기, 방장 넘기기
- 인원 상한(운영 8, 기술 10)
- 폴더별 알림 켜기/끄기

### D. 장소 옮기기·담기
- 상세 시트와 여러 개 선택 바(`SelectedPlacesBar`)에 "다른 폴더로 옮기기 / 담기"
- 같은 가게 충돌 시 합치기
- 원본 인스타 연결·저장자 기록·메모 버전도 함께 이동

### E. 저장 흐름
- 저장할 때 폴더 고르기(기본값: 마지막 사용 폴더)
- 인스타 공유 → 폴더 선택 → 기존 추출 흐름
- Android 홈 화면 앱의 공유 대상 등록(Web Share Target)
- iOS는 단축어 유지 → 나중에 네이티브 래퍼로 공유 버튼 지원

### F. 장소 정보 강화
- **전화번호**: 카카오 응답의 `phone` 저장 + 전화 걸기 버튼(지금 응답에 이미 있음)
- **네이버 플레이스 연결**: 카카오 장소를 상호·주소·좌표로 네이버 플레이스와 짝짓기
- **사진 최대 5장, 메뉴/가격, 영업시간**: 연결된 네이버 플레이스에서 가져오기
- **캐치테이블**: 매장을 찾으면 버튼 표시 + 매장 페이지로 바로 연결, 없으면 버튼 없음
- **네이버 지도 열기·네이버 예약**(예약 가능 가게만)
- 가게 정보는 **폴더와 상관없이 가게 하나당 한 번만** 저장(캐시)하고 주기적으로 새로 고침

### G. 함께 쓰기 (둘이·친구)
- 누가 저장했는지 표시(지금도 기록은 있음)
- 친구 폴더: **멤버별 "가고 싶어요" 표시·투표**("3명이 가고 싶어함")
- 둘이 폴더: 다녀온 기록(날짜·사진·한줄평), 기념일, "오늘 어디 갈까" 랜덤 뽑기

### H. 저장 경로 확장
- 장소 등록 과정 재설계(기존 미착수 과제)
- 네이버 블로그·유튜브 링크, 스크린샷 글자 인식, 영상 자막·음성
- 게시물에서 추천한 메뉴 뽑기("크림파스타 꼭 드세요")

### I. 공개 준비
- 개인정보 처리방침·이용약관 페이지, 탈퇴
- 사용자별 AI 분석·외부 조회 한도(비용 관리)
- 오류 모니터링, 간단한 관리자 화면
- 서비스 이름·소개 페이지(혼자·친구 모드까지 담는 이름)
- 나중에: 로그인 없이 보는 공개 지도 링크, 팔로우

## 4. 데이터 구조 변경

지금 코드의 **"보드"를 그대로 "폴더"로 쓴다.** 장소·원본·모음·휴지통·실시간 동기화가 이미 `board_id`로 나뉘어 있어서, 바뀌는 건 주로 로그인과 "누가"를 기록하는 방식입니다.

| 지금 | 바뀐 뒤 |
| --- | --- |
| 배포 하나에 보드 하나(`src/lib/access.ts`의 `defaultBoard`, `APP_BOARD_ID`) | 사용자 한 명이 여러 폴더(보드)에 속함 |
| 날짜 PIN + 기기 세션이 보드 하나에 묶임(`access_sessions.board_id`) | 로그인 세션은 **사용자**에 묶이고, 요청마다 **폴더 id + 멤버 여부** 확인 |
| "누가"를 이름 문자열로 기록(`member_name`, `shared_by`, `memo_updated_by`, `deleted_by`, `work_owner` — 마이그레이션 002~010 곳곳) | `user_id` + 표시용 이름 |
| `boards.member_names` 배열 | `folder_members` 테이블 |

새 테이블(안):
- `profiles`: 사용자 id, 닉네임, 사진, 탈퇴 시각
- `folder_members`: 폴더 id, 사용자 id, 역할(방장/멤버), 참여 시각, 알림 여부. **폴더당 인원 상한을 DB에서 강제**(기술 10, 운영값 8은 설정)
- `folder_invites`: 폴더 id, 토큰 해시, 만든 사람, 만료, 끊은 시각
- `boards`에 추가: 방장 id, 색, 아이콘, 기본 폴더 여부, 인원 상한. `pin_hash`·`member_names`·`token`은 이전 후 제거
- `place_details`(가게 정보 캐시, 카카오 장소 id 기준): 전화, 네이버 플레이스 id, 사진 목록, 메뉴, 영업시간, 캐치테이블 매장 주소, 마지막 조회 시각
- 나중에 `place_reactions`(멤버별 가고 싶어요)

로그인 방식(2026-11-24 구현 시 변경): Supabase Auth 대신 **서버에서 카카오·구글 OAuth를 직접 처리**합니다. 기존의 HttpOnly 세션 쿠키·해시 저장·Origin 검사 구조를 그대로 쓰고, Supabase Auth 쿠키나 카카오 이메일 필수 조건을 새로 들이지 않기 위해서입니다. DB 접근은 지금처럼 **서버의 service role + 폴더 멤버 확인**입니다. `boardFromRequest`가 돌려주는 `Board` 모양을 유지하고 `userId`만 더했습니다. 실제 테이블 이름은 `app_users`, `user_identities`, `board_members`입니다(아래 표의 `profiles`·`folder_members`에 해당).

## 5. 진행 순서 (추천)

**로그인·폴더가 맨 먼저**입니다. 초대·옮기기·멤버별 반응·폴더별 알림이 전부 "누가, 어느 폴더에서"를 알아야 동작하고, DB의 이름 기록 방식도 이때 바뀌기 때문입니다. 장소 정보 강화(F)는 계정과 독립적이라 중간에 끼워 넣을 수 있습니다.

| 단계 | 내용 | 끝나면 되는 것 | 규모 |
| --- | --- | --- | --- |
| **0. 준비** | 카카오 개발자 앱의 로그인 동의항목(이메일 필요 여부), 구글 OAuth 클라이언트, Supabase Auth 설정 확인. 작업 브랜치와 테스트 DB | 로그인 공급자 키 준비 | 작음 |
| **1. 계정 + 폴더 기반** | 로그인 화면, `profiles`, 가입 시 "내 장소" 생성, 세션→사용자 전환, 요청마다 폴더 멤버 확인, 이름 기록→`user_id`, 기존 데이터 이전, PIN 제거 | **혼자 쓰기** 가능. 우리 둘 데이터는 공유 폴더로 이전 | 큼 |
| **2. 폴더 관리 + 초대** | 폴더 만들기·수정·삭제(0개), 폴더 전환·전체 보기, 초대 링크, 멤버 관리, 방장 권한, 폴더별 알림 | **둘이·친구 폴더** 가능 | 큼 |
| **3. 옮기기·담기 + 저장 시 폴더 선택** | 상세 시트·여러 개 선택에서 옮기기/담기, 충돌 합치기, 저장 흐름에 폴더 고르기 | 폴더 사이 정리 | 중간 |
| **4. 장소 정보 강화** | 전화번호 → 네이버 플레이스 연결(사진·메뉴·영업시간) → 캐치테이블 매장 버튼 → 네이버 지도·예약 | 쏙핀 수준의 장소 상세 | 중간 |
| **5. 함께 쓰기 기능** | 멤버별 가고 싶어요·투표, 다녀온 기록, 기념일, 랜덤 뽑기 | 모드별 차별화 | 중간 |
| **6. 저장 경로 확장** | 장소 등록 재설계, 블로그·유튜브, 스크린샷, Android 공유, 추천 메뉴 | 저장 편의성 | 큼 |
| **7. 공개 준비** | 약관·처리방침, 탈퇴, 사용량 한도, 모니터링, 서비스 이름·소개 페이지 | **공개 배포** | 중간 |

- 전화번호 저장(4단계의 첫 항목)은 하루 안에 끝나는 작은 일이라, 원하면 1단계 전에 먼저 넣어도 됩니다.
- 모든 단계의 새 화면은 가로 모드부터 설계하고, 필수 5개 크기(320×568, 568×320, 667×375, 844×390, 932×430)에서 실측합니다.
- 각 단계는 마이그레이션 번호가 이어지므로(011, 012, …) 같은 시기에 두 단계를 따로 진행하면 번호가 충돌할 수 있습니다. 병행하려면 번호를 미리 나눕니다.

## 6. 단계 1 세부 작업

## 위험 메모 (지금은 보류)

사용자 결정으로 지금은 고려하지 않지만, 공개 배포 전에 다시 봅니다.

- 네이버 플레이스·캐치테이블 데이터는 **공개 API가 없어** 내부용 주소를 비공식으로 사용한다. 약관, 형식 변경, 서버 IP 차단, 사진 권리 문제가 있다.
- 인스타 본문을 링크 미리보기 봇처럼 읽어오는 방식(`src/lib/instagram.ts`)은 사용자가 늘면 차단될 수 있다.
- "내 위치" 기능이 있어 위치기반서비스사업 신고 대상인지 확인이 필요하다.
- AI 분석·외부 조회 비용이 사용자 수에 비례해 늘어난다.
