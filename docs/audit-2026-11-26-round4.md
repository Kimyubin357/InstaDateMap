   - 재현: 우리 데이트맵 방에서 "토러스"(서울 용산구 신흥로 81, 방금 지도에서 연 곳)를 검색하면 0곳입니다. 주소 "신흥로 81"이나 다른 이름("백제")은 찾습니다.

   - 고치는 방향: 검색어와 이름·주소·메모를 모두 `normalize("NFC")`로 비교하고, 저장할 때도 NFC로 넣습니다. 기존 행은 한 번 정리합니다.

## 완성도가 무너지는 곳 — 시뮬레이터에서 본 것

10. **지역 카드가 서로를 거의 다 가림.** 전국 화면에서 "서울 27" 뒤로 경기 카드의 숫자가 안 보이고, 서울 구 단계에서는 "강남구" 숫자가 송파구·서초구 카드 뒤에 숨습니다. 겹쳐 쌓는 규칙(11-07 결정)은 유지하더라도, 숫자가 가려지는 카드는 살짝 밀어내거나 숫자를 합쳐야 읽힙니다.
11. **핀 이름표가 지도 글자와 뭉개짐.**
    - 우리 핀 이름이 카카오 기본 지도의 같은 가게 이름 바로 위에 겹쳐 "토러스"가 두 번 겹쳐 보입니다(100m 단계).
    - 역 이름 등과도 겹칩니다("고코"+"광화문역", "백제정육점"+"문"). 바탕 없는 이름표라 붐비는 도심에서 읽기 어렵습니다. 글자 테두리(흰 halo)나 가까운 단계에서는 카카오 POI 이름을 숨기는 방법이 있습니다.
    - 핀끼리도 이름표가 서로 겹치고, 이름표를 누르면 아래에 깔린 다른 핀이 열릴 수 있습니다(`map-clusters.ts:124,136` — 겹침은 30px 원만 계산).
12. **같은 장소인데 지도 핀과 리스트 아이콘이 다름.** 찜질방이 지도에서는 ♨ 그림, 리스트·모음 줄·검색에서는 일반 핀 아이콘입니다. 지도는 41가지(`map-glyphs.ts`), 리스트는 8가지(`place-presentation.ts` `categoryIcon`)로 따로 고릅니다.
13. **모음 지도 시트의 목록이 하단 지도/리스트 탭 뒤로 들어감.** 두 번째 줄 분류·지역 글자가 탭 알약에 가려집니다. 시트가 열려 있을 때는 탭을 숨기거나 시트 끝 여백을 탭 높이만큼 둬야 합니다.
14. **상세 사진이 들어올 때 빈 점선 상자 두 개가 2초쯤 그대로 보임.** 로딩 표시가 없어 "사진 없음"처럼 보입니다. 리스트 줄도 아이콘으로 있다가 사진으로 툭 바뀝니다.
15. **상세 끝까지 화면에서 영업시간이 두 번 나옴.** 위 칩 "영업 전 · 12:00~21:20"과 아래 줄 "영업 전 · 12:00에 영업 시작".
16. **방 리스트 머리에 장소 수가 세 번.** 방 머리띠 "장소 52곳", 탭 "장소 52", 제목 "저장한 장소 52곳". "미분류 49" 칩은 무엇을 거르는지 이름만으로 알기 어렵습니다(모음에 안 넣은 장소).
17. **방을 바꾸면 리스트가 이전 스크롤 위치에서 시작.** 우리 데이트맵 중간까지 내린 상태에서 전체로 바꾸면 새 목록이 첫 줄이 잘린 채 중간부터 보입니다. 범위가 바뀌면 맨 위로 가야 합니다.
18. **검색 첫 화면에 "최근 검색" 제목만 있고 기록은 없음.** 기록이 0개면 제목 대신 안내만 두는 편이 자연스럽습니다. 검색 중에는 "새로 찾은 장소 0곳"이 먼저 보였다가 숫자가 바뀝니다(로딩 중에는 숫자를 숨기기).
19. **내 방 시트에서 방을 고른 뒤 바로 다음 탭이 한 번 먹히지 않는 때가 있음.** 검색 취소 직후 방 버튼을 한 번 눌렀을 때 열리지 않았습니다(전환 중 입력 무시로 추정).
