| 기존 UI 영향 | 없음. 명세와 스킬만 읽음 | **있을 수 있음.** 명세를 쓰며 기존 코드를 읽은 뒤 제작 |
| 그린 범위 | S1~S8 전부. 묶음 단계 페이지(25곳 × 4단계 × 6크기) | S2 흐름, S4·S5 새 장소, 가로 홈·묶음·상세, 홈 화면 6크기 |

## 두 시안이 같은 답을 낸 것 (적용 확신도 높음)

서로 다른 방식으로 만든 두 시안이 같은 결론에 도달한 항목입니다.

1. **1곳은 숫자로 바꾸지 않습니다.** 상태 기호와 이름으로 표시합니다.
2. **숫자 원 대신 지역 이름표**를 씁니다. 예: "성수동 12곳". 의미를 알 수 없던 다녀온 비율 링은 없앱니다.
3. **묶음을 누르면 그 묶음 범위로 한 번에 맞추고, 동시에 목록을 엽니다.** 2단계씩 반복 확대하던 동작은 없앱니다. 축소 상태에서도 2번 누르면 미리보기에 도착합니다.
4. **새 장소가 섞인 묶음에는 NEW 개수를 붙입니다.** 축소해도 새 장소가 사라지지 않습니다.
5. **등록 직후와 상대가 넣은 새 장소는 같은 화면 방식**으로 보여 줍니다. 새 장소 전부에 범위를 맞추고, ①②③ 번호를 붙이고, 나머지 장소는 흐리게 둡니다.
6. **가로에서는 좌우 노치를 피하고 + 버튼을 오른손 엄지 자리**에 둡니다.

## 알려진 문제

**시안 A**
- 568×320에서 카드를 열면 지도 폭이 약 120px로 좁습니다. 미리보기·확인 대기·알림이 동시에 뜨는 프레임에서는 선택 표시가 알림에 약 9px 걸칩니다.
- 320×568에서는 카드가 열려 있는 동안 아래 이동 줄을 숨깁니다. 다른 크기와 동작이 다릅니다.
- 동네 단계에서 기호 간격이 약 30px입니다. 그래서 지도 기호끼리는 44px 터치 영역이 겹칠 수 있습니다. 손가락 근처에 기호가 여럿이면 그 자리의 목록을 띄우는 규칙을 가정했지만 그리지는 않았습니다.
- 그리지 않은 화면: 검색, 설정, 리스트 탭 내부, 위치 권한 거부.

**시안 B**
- 실측하지 않았습니다.
- 그리지 않은 흐름: S1 빈 상태·오류, S6 필터, S7 메모 충돌·나가기 확인, S8.
- 기존 코드를 읽은 뒤 만들었기 때문에 독립적인 비교 대상으로는 약합니다.

## 권장

**시안 A를 기본으로 삼고, B에서 다음을 가져오는 방향을 권합니다.**

1. 새 장소 모드의 **명시적 [완료]**. 모드 종료 방법을 분명히 합니다.
2. 동네 단계 펼치기의 구현 비용이 크면 단계적으로 갑니다. 1차는 **B의 "같은 건물 N" 작은 묶음**으로 출시하고, 펼치기는 2차로 미룹니다.

UI/UX Pro Max 스킬의 효과는 제한적이었습니다. 지도 기호·묶음에 관한 지침은 없었고, 터치·안전영역·피드백 같은 일반 점검표로만 쓰였습니다. 시안 A의 품질은 스킬 자체보다 **명세만 보고 격리해서 설계한 방식**과 **자동 실측**에서 나온 부분이 큽니다.

## 확정안 (2026-11-07, 1단계: S1 처음 열기 + S2 일부)

사용자와 문답으로 확정했습니다. 이 목록 외의 화면·동작은 임의로 바꾸지 않습니다.

**바꾸지 않는 것:** 장소 상세, 미리보기 카드, 내 위치·전체 보기 버튼, 하단 지도/리스트 탭, + 버튼, 리스트 탭의 상태 표시, 충분히 확대했을 때의 개별 장소 이름 핀.

1. **기본 필터:** 지도·리스트 공통(필터 하나를 같이 씀) 기본값은 가고 싶음 + 또 갈래입니다. 필터 초기화도 이 상태로 돌아가며, 필터 걸림 점은 기본 상태에서도 표시합니다.
2. **NEW 기준(모든 NEW 표시 공통):** 등록 24시간 이내이면서 상태가 가고 싶음인 장소만 NEW입니다. 누가 넣었든 같습니다. 다녀옴·또 갈래·별로로 바뀌면 NEW에서 빠집니다.
3. **검색 줄(세로·가로):** [검색 입력칸(폭 줄임)] [필터] [설정] 순서입니다. 그 아래 왼쪽 정렬로 확인 대기 링크(우선), 그 아래에 ‘NEW 새 장소 N’을 둡니다.
   - 새 장소 숫자는 필터와 관계없이 셉니다.
   - 버튼을 눌렀을 때의 동작은 다음 단계에서 개발하며, 지금은 눌러도 반응이 없습니다.
4. **집계 카드:**
   - 기존 숫자 원 대신 지역별 카드 한 장으로 표시합니다. 1곳도 같은 카드입니다.
   - 카드 안에는 지역명(서울 → 성동구 → 성수1가1동)과 가고 싶음 개수만 넣습니다. 또 갈래만 있으면 0을 보여 줍니다. 지역 조회에 실패하면 숫자만 보여 줍니다.
   - 새 장소가 섞이면 NEW와 숫자 배지를 붙입니다.
   - 카드 밑면의 진행 바는 그 지역 전체 장소(필터에 가려진 장소 포함) 중 다녀온 비율입니다.
   - 시·구 단계에서 카드끼리 겹치면 지도에 보이는 장소가 많은 지역을 보여 줍니다. 가려진 지역은 숫자에 더하지 않습니다. 동 단계의 겹침은 사용자가 확인한 뒤 정합니다.
5. **카드 탭:**
   - 시·구 카드는 그 묶음 범위로 한 번에 확대합니다(묶음 유지).
   - 동 카드는 범위를 맞추고 목록 시트를 엽니다. 1곳 카드는 기존처럼 미리보기를 엽니다.
6. **동 단계 목록:**
   - 세로는 A안 S2를 참고하며, 네비 탭 위에서 멈추고 X 닫기만 둡니다.
   - 가로는 A안 왼쪽 열을 참고합니다.
   - 행을 누르면 기존 미리보기 카드가 열립니다.
7. **상태창:**
   - 대상은 불러오는 중, 장소 0곳, 장소 불러오기 실패, 지도 로드 실패, 필터 결과 0곳입니다.
   - **세로:** 화면 가운데 모달로 띄우고, 화면 전체를 어둡게 덮어 조작을 막습니다.
     - 불러오는 중은 닫기가 없고 끝나면 저절로 사라집니다.
     - 나머지는 X로 닫을 수 있으며, 같은 상황이 다시 생기면 또 띄웁니다.
     - 0곳 모달에는 ‘장소 추가’, 필터 0곳 모달에는 ‘필터 초기화’ 버튼을 둡니다.
   - **가로:** A안 그대로 왼쪽 열 카드 자리에 둡니다.
   - **고민 기록:** 어두운 덮개로 지도 조작을 막을지는 사용자가 고민 중입니다. 일단 덮개로 막고, 써 본 뒤 바꿀지 결정합니다.

### 구현 중 발견한 사항 (결정 필요)

1. **동 카드를 눌러도 카드 단계에 머무는 경우가 많습니다.** 목록 시트가 화면 절반을 덮어 지도에 남는 영역이 좁기 때문입니다. 장소들이 들어오도록 맞추면 확대 단계가 이름 핀 경계(레벨 3)까지 내려가지 않아, 같은 동 카드가 다시 보입니다.
   - 선택지: 동 카드는 이름 핀 단계까지 강제로 확대합니다(일부 장소는 화면 밖). 또는 지금처럼 범위 맞춤을 우선합니다.
2. **세로 목록 시트가 오른쪽 아래 지도 도구를 덮습니다.** 시트가 열려 있는 동안 전체 보기·내 위치·+ 버튼이 가려집니다. 기존 필터·상세 시트와 같은 방식입니다.
   - 선택지: 그대로 둡니다. 또는 장소 카드처럼 도구를 시트 위로 올립니다(도구 위치 변경).
3. **기존 ‘전체 보기’의 범위 맞춤 여백이 고정값입니다.** 그래서 568×320에서 지역 카드가 검색 줄 아래로 일부 가려집니다. 새 여백 계산을 전체 보기에도 쓰면 해결되지만, 버튼 동작이 바뀌므로 확인이 필요합니다.
4. **필터 자동 조정:** 저장 직후 도착과 ‘지도에서 보기’는 필터를 기본값으로 돌립니다. 다만 그 장소가 다녀옴·별로라 숨겨지는 경우에만 전체 상태로 넓혀 장소가 보이게 했습니다. 이 동작이 맞는지 확인이 필요합니다.
5. **짧은 가로의 알림 위치:** 짧은 가로에서는 알림(토스트)이 검색 줄 아래 왼쪽에 뜨는 기존 규칙이 있어, 확인 대기·새 장소 칩과 겹칠 수 있습니다. 확인 대기 배지와는 이전부터 겹치던 위치이며, 이번에 실측하지 않았습니다.
6. **44px 미만인 요소:** 확인 대기 배지 높이 41px(기존 디자인), 지도 도구 42px(변경 금지 대상). 이번에는 바꾸지 않았습니다.
7. **가려지는 지역:** 시·구 단계에서 가려지는 지역이 생깁니다(예: 모의 데이터에서 용산구가 성동구에 가려짐). 확정 규칙대로의 동작이며, 실제 지도에서 확인이 필요합니다.
8. **`next dev`가 저장소 파일을 바꿉니다.** 실행할 때마다 AGENTS.md 끝에 Next.js 안내 블록을 넣고 `next-env.d.ts`를 바꿉니다. 이번에는 되돌렸습니다. `next.config.mjs`에 `agentRules: false`를 둘지 결정이 필요합니다.
9. **다음 단계:** 새 장소 버튼을 눌렀을 때의 동작은 아직 연결하지 않았습니다.

## 1.1단계 조정 (2026-11-07, 실기기 피드백)

- **단계 재설계:** 카카오 레벨 기준으로 도 12–14(32km~128km) · 시 9–11(4km~16km) · 구 7–8(1km~2km) · 동 4–6 · 이름 핀 3 이하로 나눴습니다.
  - 도 이름은 짧게 씁니다(경기·충북·전북·제주). 광역시는 서울·부산처럼 그대로 씁니다.
- **겹침 처리:** 카드를 숨기지 않고 겹쳐 둡니다. 장소가 많은 카드가 위에 오고, 같으면 가나다순으로 앞선 지역이 위에 옵니다.
  - 이전 숨김 규칙에서는 "수원 8곳이 서울에 가려지고 화성 1곳만 보이는" 문제가 있었습니다.
- **화성시 카드:** 가짜 데이터가 아니었습니다. 지역은 좌표의 행정동으로 판정하므로, 수원 경계 근처 장소가 화성시로 집계될 수 있습니다.
- **동 목록 닫기:** 목록 바깥을 탭하면 닫힙니다.
  - 다른 동 카드를 누르면 그 동 목록으로 바뀝니다.
  - 검색·필터·설정·확인 대기·새 장소·네비·지도 도구를 누르면 목록이 닫히고 그 버튼이 그대로 동작합니다.
  - 지도를 끌어 움직이는 동작은 목록을 닫지 않습니다.
- **검증:**
  - 타입 검사와 자동 테스트 530개가 통과했습니다.
  - 가짜 지도와 모의 장소 51곳(서울 7개 동, 경기 7개 시, 인천·청주·대전·부산)으로 393×852에서 레벨 14→4를 측정했습니다. 다른 카드에 완전히 가려지는 카드는 없었습니다.

## 1.2단계: 카드를 눌러도 반응이 없던 문제 (2026-11-07)

- **원인:** 여러 곳이 담긴 카드를 누르면 "그 지역 장소 전체가 들어오도록" 범위를 맞추게 되어 있었습니다. 그런데 서울처럼 넓게 퍼진 지역은 이미 같은 레벨에서 다 보이거나, 다 넣으려면 더 넓은 레벨이 필요합니다. 그래서 지도가 그대로이거나 오히려 축소됐습니다.
- **수정:** 카드를 누르면 **이름이 실제로 바뀌는 다음 단계까지는 반드시 확대**합니다.
  - 확대 목표: 도 → 시(레벨 11), 시 → 구(8), 구 → 동(6).
  - 이름만 같은 단계는 건너뜁니다. 서울 도 → 구, 세종 도 → 동, 과천시 시 → 동.
  - 범위 맞춤 결과가 목표보다 더 확대된 레벨이면 그쪽을 씁니다.
  - 범위가 목표보다 넓게 나오면 장소들의 중심을 기준으로 목표 레벨로 확대합니다. 이 경우 일부 장소는 화면 밖에 있을 수 있습니다.
  - 장소가 한곳에 몰려 있어도 이름 핀 단계(레벨 3)보다 더 깊이 확대하지 않습니다. 이전에는 카카오 최대 확대(레벨 1)까지 들어갈 수 있었습니다.
- **검증:**
  - 자동 테스트 533개가 통과했습니다.
  - 가짜 지도(393×852)에서 확인한 결과: 서울은 레벨 10·9·13에서 눌러도 모두 구 단계(레벨 8)로 들어가며, 레벨 9에서 축소되던 현상이 없어졌습니다. 세종과 과천시는 레벨 3 이름 핀에서 멈췄습니다.
  - 실기기 확인은 필요합니다.
