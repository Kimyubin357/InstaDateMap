## 두 시안이 같은 답을 낸 것 (적용 확신도 높음)

서로 다른 방식으로 만든 두 시안이 같은 결론에 도달한 항목입니다.

1. **1곳은 숫자로 바꾸지 않습니다.** 상태 기호와 이름으로 표시합니다.
2. **숫자 원 대신 지역 이름표**를 씁니다. 예: "성수동 12곳". 의미를 알 수 없던 다녀온 비율 링은 없앱니다.
3. **묶음을 누르면 그 묶음 범위로 한 번에 맞추고, 동시에 목록을 엽니다.** 2단계씩 반복 확대하던 동작은 없앱니다. 축소 상태에서도 2번 누르면 미리보기에 도착합니다.
4. **새 장소가 섞인 묶음에는 NEW 개수를 붙입니다.** 축소해도 새 장소가 사라지지 않습니다.
5. **등록 직후와 상대가 넣은 새 장소는 같은 화면 방식**으로 보여 줍니다. 새 장소 전부에 범위를 맞추고, ①②③ 번호를 붙이고, 나머지 장소는 흐리게 둡니다.
6. **가로에서는 좌우 노치를 피하고 + 버튼을 오른손 엄지 자리**에 둡니다.

## 갈리는 지점 (사용자 결정 필요)

| 쟁점 | 시안 A | 시안 B | 의견 |
|---|---|---|---|
| 묶음 이름표 둘째 줄 | "가고 싶음 7"만 표시 | "○8 ●3 ◎1" 상태 전부 표시 | A가 더 읽기 쉽습니다. "가고 싶은 곳이 어디"라는 성공 기준에도 직접 답합니다 |
| 동네 단계의 겹침 | **묶지 않음.** 겹친 기호를 둘레로 펼치고 점선으로 실제 위치를 가리킴. 이름표는 우선순위대로 일부만 표시 | 동네 단계에서도 "같은 건물 2"처럼 작은 묶음 허용 | A가 더 직관적입니다. 다만 펼치기 계산이 새로 필요해 구현 비용이 큽니다 |
| 상태 기호 | 빈 원 / 체크 / 하트 / 점선 원 | ○ / ● / ◎ / ⊘ | A는 뜻이 그림에 드러납니다. B는 범례에 의존합니다 |
| 새 장소 확인 방식 | 결과 카드가 "저장했어요" 알림을 겸하고, 카드 안에서 상태와 메모를 바로 수정 | 상단 "새로 담은 3곳" 배너 + [완료]로 모드 종료, 카드에서 메모·자세히 | A는 단계가 적습니다. B의 명시적 [완료]는 모드에서 빠져나오기 쉬움 |
| 상세의 상태 4종 | 하단 고정 줄(엄지 자리), 누르면 즉시 저장 | 상세 맨 위 큰 버튼 + 미리보기 카드에 상태 버튼 | A가 한 손 조작에 유리합니다 |
| + 버튼 (세로) | 하단 줄 오른쪽 큰 "장소 추가", 왼쪽은 지도/리스트 전환 | 하단 탭 가운데 "장소 담기" | 비슷합니다. A는 지도/리스트 전환과 한 줄에 묶여 더 간결합니다 |
| 확인 대기 링크 | 위쪽 상태 칩 줄에 표시 | + 버튼 위 숫자 배지 | A가 더 잘 보입니다. B는 놓치기 쉽습니다 |
| 가로 배치 | 왼쪽 열(검색+카드), 지도 위 가운데(칩), 오른쪽 열(도구·+) | 왼쪽 패널 하나에 검색·필터·목록·상세를 모두 담음 | B는 일관되지만 높이 320에서 목록이 2줄뿐입니다. A는 568에서 카드가 열리면 지도 폭이 약 120px로 줄어듭니다 |

## 알려진 문제

**시안 A**
- 568×320에서 카드를 열면 지도 폭이 약 120px로 좁습니다. 미리보기·확인 대기·알림이 동시에 뜨는 프레임에서는 선택 표시가 알림에 약 9px 걸칩니다.
- 320×568에서는 카드가 열려 있는 동안 아래 이동 줄을 숨깁니다. 다른 크기와 동작이 다릅니다.
- 동네 단계에서 기호 간격이 약 30px입니다. 그래서 지도 기호끼리는 44px 터치 영역이 겹칠 수 있습니다. 손가락 근처에 기호가 여럿이면 그 자리의 목록을 띄우는 규칙을 가정했지만 그리지는 않았습니다.
- 그리지 않은 화면: 검색, 설정, 리스트 탭 내부, 위치 권한 거부.

**시안 B**
- 실측하지 않았습니다.
- 그리지 않은 흐름: S1 빈 상태·오류, S6 필터, S7 메모 충돌·나가기 확인, S8.
- 기존 코드를 읽은 뒤 만들었기 때문에 독립적인 비교 대상으로는 약합니다.

## 권장

**시안 A를 기본으로 삼고, B에서 다음을 가져오는 방향을 권합니다.**

1. 새 장소 모드의 **명시적 [완료]**. 모드 종료 방법을 분명히 합니다.
2. 동네 단계 펼치기의 구현 비용이 크면 단계적으로 갑니다. 1차는 **B의 "같은 건물 N" 작은 묶음**으로 출시하고, 펼치기는 2차로 미룹니다.

UI/UX Pro Max 스킬의 효과는 제한적이었습니다. 지도 기호·묶음에 관한 지침은 없었고, 터치·안전영역·피드백 같은 일반 점검표로만 쓰였습니다. 시안 A의 품질은 스킬 자체보다 **명세만 보고 격리해서 설계한 방식**과 **자동 실측**에서 나온 부분이 큽니다.
