# 단순 구조 규칙 (격리됨 — 요청이 있을 때만 적용)

> ## ⛔ 적용 조건
> 이 문서는 **사용자가 특정 화면을 직접 지목해서 "이 화면(부분)을 리디자인해줘"라고 요청했을 때만** 읽고 적용합니다.
>
> - 적용 범위는 **사용자가 지목한 화면·부분뿐**입니다. 같은 작업 중이라도 지목하지 않은 화면에는 적용하지 않습니다.
> - 그 밖의 작업에는 이 규칙을 **적용하지 않습니다.** 버그 수정, 기능 추가, 새 화면 만들기, 레퍼런스를 받아 특정 화면을 바꾸는 작업, "UI 정리" 같은 일반 요청이 모두 해당합니다. 이런 작업은 기존 [디자인 철칙](../design-principles.md)과 지금 화면 구조를 따릅니다.
> - 이 규칙을 근거로 요청받지 않은 화면을 고치거나 고치자고 제안하지 않습니다. 이 규칙에 맞추려고 설명 문구·버튼을 미리 빼지도 않습니다.
> - 애매하면(예: "이 화면 좀 이상해") 적용하지 말고, 이 규칙으로 리디자인할지 먼저 묻습니다.

작성: 2026-11-24. 근거는 사용자가 준 레퍼런스 4장(로그인·약관 동의·약관 보기·프로필 수정)의 공통 구조입니다. 기록은 [레퍼런스로 바꾼 화면 기록](../design-reference-log.md)에 있습니다.

## 바꾸지 않는 것

- **테마는 그대로 둡니다.** 아이보리·크림 원단, 박다현체, 붉은/초록 잉크, 점선, 인쇄 그림자, 아이콘 체계는 [디자인 철칙](../design-principles.md)을 따릅니다. 이 규칙은 **구조**(무엇을, 어떤 순서로, 몇 개 두는지)만 다룹니다.
- 지도 도구(내 위치·전체 보기·하단 탭·+ 버튼)는 사용자 확정 사항이라 그대로 둡니다.
- 가로 모드 필수 크기 실측, 44px 터치 영역, 접근성 이름, 한국어 오류 문구 같은 품질 기준도 그대로 지킵니다.

## 규칙

### 1. 화면 하나에 할 일 하나
- 화면의 목적을 한 문장으로 말할 수 없으면 둘로 나눕니다.
- 주요 실행 버튼은 **하나**입니다. 세로 화면에서는 맨 아래에 폭 전체로 두고, 조건이 안 되면 비활성으로 보여 줍니다.
- 보조 동작(삭제, 나가기 등)은 화면 맨 아래 작은 글씨 버튼이나 `⋯` 메뉴로 옮깁니다.

### 2. 머리글은 얇게
- 왼쪽 `<`, 가운데 제목만 둡니다. 오른쪽은 비우거나 아이콘 하나만 둡니다.
- 머리글 아래에 화면을 다시 설명하는 문단(리드 문장)을 두지 않습니다. 꼭 필요하면 한 줄로 씁니다.

### 3. 목록 줄은 제목과 `>`만
- 줄 하나 = 아이콘(선택) + 제목 + 오른쪽 값이나 `>`입니다.
- 줄마다 붙는 회색 설명(부제)은 기본으로 넣지 않습니다. 눌러 봐야 알 수 있는 정보만 예외로 한 줄 씁니다.
- 줄 사이는 구분선 하나로 나눕니다. 짧은 내용을 카드로 감싸지 않습니다.

### 4. 선택지는 펼치지 말고 눌러서 연다
- 3개 이하의 선택은 줄을 누르면 아래에서 올라오는 선택 시트로 엽니다(프로필 사진 선택 방식).
- 화면 안에 버튼 줄, 펼침 영역, 토글 묶음을 상시로 두지 않습니다. 스위치 하나로 끝나는 설정은 예외입니다.

### 5. 안내 문장은 한 번만, 짧게
- 같은 뜻을 제목·설명·버튼·도움말에서 반복하지 않습니다.
- 입력칸 아래 도움말은 틀렸을 때(오류)만 보여 줍니다. 평소에는 라벨과 자리표시 글자로 충분하게 만듭니다.
- 문장보다 라벨을 씁니다. 예: "장소를 저장하면 폴더 멤버에게 이 이름으로 보여요" 대신 "닉네임".

### 6. 입력 화면은 라벨 + 칸 + 저장
- 위에서부터 대표 요소(사진 등) → 라벨 → 입력칸 → (빈 공간) → 맨 아래 저장 순서입니다.
- 바꾼 게 없으면 저장은 비활성입니다. 보조 버튼("○○로 되돌리기")은 두지 않거나 시트 안으로 넣습니다.

### 7. 단계는 나눠서 한 번에 하나씩
- PIN 확인 → 이름 선택처럼 순서가 있는 일은 한 화면에 다 펼치지 않고 단계별로 보여 줍니다.
- 앞 단계가 끝나야 다음 단계의 요소가 나타납니다.

### 8. 빈 상태·오류도 같은 구조
- 빈 화면에는 그림(선택), 한 줄 제목, 버튼 하나만 둡니다.
- 오류는 한 줄 문장과 "다시 시도" 버튼 하나만 둡니다.

## 리디자인 요청을 받았을 때 순서

1. 사용자가 지목한 화면·부분을 확인합니다. 범위가 애매하면 묻습니다.
2. 지금 구조를 위 규칙에 대 보고 **뺄 것 / 합칠 것 / 시트로 숨길 것**을 정리합니다.
3. 코드를 고치기 전에 "지금 구조 → 바꿀 구조"를 짧은 글 배치도로 보여 주고 승인을 받습니다. 사용자가 바로 적용하라고 하면 생략합니다.
4. 지목한 범위만 고칩니다. 필수 5개 크기(320×568, 568×320, 667×375, 844×390, 932×430)와 393×852·1440×900에서 실측합니다.
5. [레퍼런스로 바꾼 화면 기록](../design-reference-log.md)에 "단순 구조 규칙 적용"으로 한 줄을 추가합니다.
