# 패브릭 실크스크린 테마

아이보리 에코백 원단에 두 가지 잉크로 인쇄한 듯한 분위기를 사용합니다. 참고 이미지의 토마토 캐릭터와 장식을 앱 전체에 반복하지 않고, 색·직조 질감·손글씨·인쇄 테두리로 같은 감성을 연결합니다.

## 화면 적용 원칙

- 실제 카카오 지도는 색 보정이나 질감 오버레이 없이 끝까지 채웁니다. 안전 영역·키보드 대응·지도 인스턴스와 기존 동작을 유지합니다.
- 숫자 핀은 붉은 원형 바탕·아래쪽 꼬리를 사용하고, 방문한 비율만 아이보리색 띠로 표시합니다. 별도의 미방문 트랙은 없습니다. 카카오 레벨 10 이상은 같은 시·군, 레벨 8~9는 같은 시·군·구, 레벨 4~7은 같은 행정 읍·면·동 안에서 실제 이름표가 겹치는 2곳 이상만 묶습니다(이름표 간 여유 8px). 레벨 3 이하는 전부 개별 장소명으로 표시합니다. 같은 구역이라도 겹치지 않거나 1곳이면 이름을 유지합니다. 행정구역은 SDK의 좌표→행정구역 조회에서 H(행정동) 결과로 확인하며, 구역을 모르면 개별 표시합니다. 수원시 장안구·권선구·팔달구는 시 단계에서 수원시로 합쳐집니다. 서울·광역시는 해당 도시로 묶되 광역시 내 군은 독립적으로 유지하며, 도가 다른 동명의 시·군은 구분합니다. 구가 없는 시·군이나 세종은 중간 단계에서 같은 구역 키를 유지합니다.
- 행정구역 조회는 장소 표시를 막지 않고 지도 인스턴스 메모리에 좌표별로 보관합니다. 중복 요청을 합치고 최대 4개씩 조회하며, 성공 결과는 하루·실패는 1분간 재사용합니다. 활성 지도에서 실패한 조회만 재시도하고 숨기거나 떠날 때 타이머를 정리합니다. DB·조회 캐시 형식 변경은 없습니다. 숫자는 필터 결과의 장소 수, 띠는 방문 비율입니다. 숫자 핀은 최대 두 단계 확대하고 최소 레벨 3까지 내려갑니다. 작은 상세 지도에는 집계 핀을 사용하지 않고 지도 인스턴스·키보드 포커스를 유지합니다.
- 검색창·카드·필터·하단 탭은 밝은 원단 위에 가는 잉크 테두리를 사용합니다. 주요 버튼은 붉은 인쇄, 선택 상태와 보조 동작은 초록 인쇄입니다.
- 리스트·검색 결과·설정은 열린 행과 박음질 구분선을 사용합니다. 작은 내용을 다시 둥근 카드로 감싸지 않습니다.
- 상세 시트는 작은 지도·큰 장소명·두 칸의 요약·상태·메모 순서를 유지합니다. 종전 요약 정보의 둥근 바탕을 제거해 같은 원단 위에 인쇄한 듯 연결합니다.
- 토스트도 초록 인쇄 라벨로 통일하고, 오류·삭제·메모 폐기 질문은 원단 다이얼로그를 사용합니다.
- 질감은 재사용하는 작은 SVG 타일 두 개입니다. 글씨나 지도 위에 노이즈 필터를 직접 걸지 않습니다. 원단 무늬는 최종 이미지가 들어와도 글자 가독성을 해치지 않는 강도로 유지합니다.
- 글씨·아이콘·버튼은 실제 UI로 유지합니다. 스플래시나 캐릭터 이미지를 버튼 대신 사용하지 않습니다.

주요 스타일은 `src/app/fabric-theme.css`, 화면 구조와 동작은 기존 컴포넌트와 `globals.css`에 있습니다.

장소 상세의 상태 버튼은 가고 싶음(붉은 잉크)·또 갈래(머스터드)·다녀옴(초록 잉크)·별로(회갈색)로 구분하며, 선택한 버튼은 같은 색의 진한 바탕으로 표시합니다. 인스타 원본은 보라·분홍·주황 그라데이션의 직접 링크 버튼으로 열고 외부 임베드는 불러오지 않습니다. 삭제는 원본 링크 아래의 보조 버튼에서 확인 창을 거쳐 실행합니다.

## 제공받아 적용한 이미지 에셋

전달받은 이미지를 아래 위치에 적용했습니다. 캐릭터 PNG의 투명도와 원본 비율을 유지합니다. 선택할 이름은 보드 설정을 그대로 사용하고, 얼굴은 사용자가 지정한 **유빈·수민 이름**에 연결합니다. 두 이름의 표시 순서가 바뀌어도 얼굴과 색이 바뀌지 않습니다. 다른 이름에는 중립 사용자 아이콘을 표시합니다.

| 전달 순서 | 적용 위치 | 보관 파일 |
| --- | --- | --- |
| 새 1번 얼굴 | 기기 주인 선택의 유빈 | `public/illustrations/yubin.png` |
| 새 2번 얼굴 | 기기 주인 선택의 수민 | `public/illustrations/sumin.png` |

| 5번 나란히 앉은 그림 | 기기 주인 선택 화면의 데이트맵 아래 | `public/illustrations/choose-couple.png` |

아이콘 원본은 그대로 보관하고 설치용 사본에서 검은 바깥 여백을 정리해 아이보리 바탕의 불투명 정사각형으로 내보냈습니다. iPhone 180px, Android 192px·512px, 브라우저 64px를 제공합니다. Android 아이콘은 새 파일명을 사용하며 이전 SVG 아이콘은 제거했습니다. 기존 홈 화면 아이콘에 새 그림이 반영되지 않으면 삭제 후 다시 추가해 확인합니다.

다섯 원본 파일이 전달본과 같은지 해시로 확인했습니다. Chrome 390×844·320×568·1440×900, WebKit 390×844에서 이미지 로드·투명 배경·전체 비율·제목 겹침 없음·가로 넘침 없음을 확인했습니다. 임시 보드에서 1번·2번 캐릭터를 각각 선택해 실제 API의 기기 사용자 이름도 검증했습니다. 설치용 PNG의 실제 응답 크기·불투명 여부·manifest 연결, PIN 숫자 입력과 표시 전환도 확인했습니다. 기존 191개 테스트·타입 검사·운영 빌드를 통과했고 임시 보드는 삭제했습니다. 실제 홈 화면 아이콘 갱신은 아이폰에서 확인합니다.

2026-10-22에 새로 받은 유빈·수민 얼굴로 교체했고 두 파일이 전달 원본과 같은지 확인했습니다. 임시 보드의 이름 순서를 뒤집어도 얼굴·색·실제 기기 사용자 선택이 일치했습니다. 위와 같은 네 브라우저·화면 크기에서 실제 장소 API 응답을 지연시켜 지도 로딩 안내와 필터 사이 16px 간격을 확인했습니다. 리스트에서는 로딩·오류 안내가 정렬 줄 아래에 표시되고, 로딩 중 필터 열기와 오류 후 재시도도 동작했습니다. 회귀 테스트 191개·타입 검사·운영 빌드를 통과했으며 임시 보드는 삭제했습니다. 모바일 안전영역은 브라우저에서 모의 검증했습니다.

## 스플래시

2026-10-26에 사용자가 최종 선택한 스플래시를 적용했습니다. 따뜻한 피부색의 커플이 지도를 함께 보고, 실제 온글잎 박다현체로 합성한 큰 `데이트맵♥` 타이틀을 사용하는 이미지입니다.

- 전달 원본: `public/splash/datemap-source.png` (1179×2556). 타이틀까지 포함한 최종 승인본을 그대로 보관합니다.
- 앱 시작: `public/splash/datemap-splash.webp`. 루트 레이아웃의 `AppSplash`가 문서를 처음 열 때 표시하며, 이미지 준비 후 최소 650ms를 채우고 180ms 동안 사라집니다. 내부 화면 이동이나 백그라운드 복귀에는 다시 나타나지 않습니다.
- 이미지 로드 실패나 지연에도 약 3초 이내 앱을 사용할 수 있으며, 자바스크립트가 실행되지 않으면 CSS가 4초 뒤 오버레이를 숨깁니다. 동작 줄이기 설정에서는 전환 효과를 생략합니다.
- iPhone 홈 화면: `src/lib/splash.ts`의 화면 크기·배율 12종에 맞춘 세로 PNG를 `apple-touch-startup-image`로 연결합니다. 원본을 자르지 않고 화면 안에 맞추며, 앱 내 스플래시도 가로 화면과 데스크톱에서 전체 그림을 유지합니다.
- 재생성: 원본 교체 후 `npm run splash:assets`. 서비스 워커의 알림 전용 동작과 API·지도 캐시 정책은 그대로입니다.

회귀 테스트 462개·타입 검사·운영 빌드를 통과했습니다. 브라우저 플러그인이 없어 Playwright와 Chrome으로 로컬 운영 빌드의 390×844·320×568·1440×900·844×390을 검증했습니다. 스플래시 표시 후 종료, 기존 입장 폼 조작, 내부 주소 변경·앱 복귀 시 재표시 없음, 가로 넘침 없음과 오류 로그 없음을 확인했습니다. 이미지 실패·지연에도 입장을 막지 않으며, 자바스크립트가 꺼져 있어도 4초 뒤 오버레이가 숨겨집니다. iOS 시스템 시작 화면과 기존 설치본의 시작 이미지 갱신은 실제 iPhone에서 별도로 확인해야 합니다.

## 아직 받지 않은 이미지 에셋

아래 목록은 후속 작업 대기 항목입니다. 제공받은 입장 그림을 임의로 빈 화면이나 스플래시에도 재사용하지 않습니다.

| 에셋 | 쓰는 곳 | 권장 전달 형태 | 그림 지침 |
| --- | --- | --- | --- |
| 첫 장소 그림 | 빈 지도·빈 보관함 | 투명 PNG, 768×512 정도 | 둘이 빈 지도를 펼치거나 작은 장소 핀을 들고 있는 간결한 그림. 글씨 제외. |
| 검색 결과 없음 그림 | 통합 검색 결과 없음 | 투명 PNG, 768×512 정도 | 돋보기·지도 같은 한 가지 상황. 색과 캐릭터 비율은 첫 장소 그림과 통일. |
| 링크 확인 필요 그림 | 장소를 찾지 못했거나 보완이 필요한 링크 | 투명 PNG, 768×512 정도 | 함께 링크·메모를 들여다보는 그림. 실패를 과하게 강조하지 않는 표정. 글씨 제외. |
| 실제 원단 질감, 선택 사항 | 지도 외 바탕·시트 | 이음새 없는 512×512 PNG 또는 WebP | 접힘·얼룩·조명·원근 없이 균일한 직조. 캐릭터와 테두리 제외. 현재 코드를 대신할 수 있는 낮은 대비. |

위 후속 그림에는 문구나 버튼을 함께 구워 넣지 않습니다. 원본 레이어 파일이 있으면 함께 보관합니다. 스플래시는 사용자가 선택한 타이틀 포함 완성본을 사용합니다.

## 시안 비교 범위

제공된 패브릭 이미지와 지도·검색·상세의 3화면 시안을 기준으로 팔레트, 원단 농도, 글씨의 크기와 분위기, 인쇄 테두리, 열린 행 배치, 작은 카드와 하단 탭을 비교합니다. 시안은 여러 화면을 합친 이미지여서 단일 화면은 모바일 390×844, 작은 화면 320×568, 데스크톱 1440×900으로 확인합니다.

실제 카카오 지명·장소·검색 결과는 시안의 예시와 다릅니다. 기존 마커의 장소명 표시, 카드의 메모·저장자, 날짜·이름·PIN·메모와 진행 안내 문구는 그대로 유지합니다. 입장·기기 주인 선택의 캐릭터와 앱 아이콘은 제공받은 에셋을 적용했고, 스플래시는 위 최종 승인본을 적용했습니다. 지도 타일 안의 지명과 외부 인스타 임베드는 해당 서비스가 제공하는 글꼴을 사용합니다.

## 적용 검증

기존 191개 테스트, 타입 검사와 운영 빌드를 통과했습니다. 앱 내 브라우저에서 입장 화면을 먼저 확인했습니다. 여러 화면 크기와 별도 임시 보드 세션을 구성하는 기능은 해당 브라우저에서 제공하지 않아 Playwright를 사용했습니다. Chrome 모바일 390×844, WebKit 390×844, 데스크톱 1440×900, 작은 화면 320×568을 확인했습니다.

임시 보드에서 실제 Supabase 조회·메모와 상태 저장, 카카오 지도·장소 검색을 사용했습니다. 카드 → 상세 → 메모·상태 저장, 메뉴의 Tab 이탈과 터치 삭제 확인 취소, 메모 폐기 질문, 검색의 첫 터치 포커스·주소 확인·취소, 리스트·필터·설정·저장·장소 확인·이름 선택·입장·최초 설정 화면을 검증했습니다. 작은 화면에서 가로 넘침이 없고 필터 하단 버튼이 보이는 것을 확인했습니다. 실제 커플의 PIN·데이터는 수정하지 않았고 임시 보드는 삭제했습니다.

제공 레퍼런스, 전체 시안과 최신 화면 캡처를 직접 열어 다음 항목을 대조했습니다.

| 항목 | 반영과 차이 |
| --- | --- |
| 팔레트 | 아이보리·붉은 잉크·초록 잉크·갈색 글씨를 지도 외 공통 화면에 적용했습니다. |
| 원단 | 작은 글자 뒤의 무늬가 강했던 첫 구현을 낮은 대비로 수정했습니다. 실제 질감 이미지 대신 경량 벡터 타일을 사용합니다. |
| 글씨 | 제공받은 박다현체가 실제로 로드되는 것을 확인했습니다. 글자 높이를 보정했고 작은 화면의 상태 버튼도 별도 크기로 맞췄습니다. |
| 테두리와 아이콘 | 가는 인쇄·박음질 선과 기존 SVG 아이콘을 사용합니다. 일러스트 속 캐릭터를 탐색 버튼에 반복하지 않습니다. |
| 배치 | 전체 지도·작은 카드·원형 도구·작은 하단 탭·전체 검색·상세 시트 구성을 유지했습니다. |
| 정보와 문구 | 화면 기능 문구는 바꾸지 않았습니다. 시안의 예시와 다른 실제 장소·저장자·검색 결과 및 기존 카드 메모를 표시합니다. |
| 반응형 | 모바일·작은 화면·데스크톱에서 같은 재질과 여백 체계를 사용하며, 화면이 낮으면 기존 스크롤로 본문을 볼 수 있습니다. |
| 후속 에셋 | 입장·기기 주인 선택 캐릭터, 하트 지도 핀 아이콘과 스플래시를 적용했습니다. 빈 화면 세 종류와 실제 원단 질감은 대기 중입니다. |

테마·주요 화면은 이 시안에 맞춰 검증했습니다. 실제 iPhone 홈 화면 앱의 상태 표시줄 합성과 시스템 키보드는 실기기로 확인해야 합니다.
